# CMA 핵심 기능 보완 결과 — 2026-10-17

사용자는 작업 재개와 불필요한 확인 생략을 지시했다. 기존 변경을 보존하며 CMA 전용 브랜치에서 초기 누적 이자 정리와 실제 일일 자동 반영 경로에 집중했다. 신규 조회 실행기·별도 NH 인증 경로는 추가하지 않았다. **로컬 기능·시험은 완료했으며, 운영 신뢰 형식 등록과 실제 장부 반영·활성화·병합·배포는 아직 수행하지 않았다.**

## 완성한 핵심 처리

1. 초기 누적 이자만 별도로 정리하는 원자적 저장과 화면/API를 추가했다. `portfolio_cma.openings`에 인식일·금액·정리 사유·전후 장부·명세/장부 증거를 남기며 과거 지급일은 지정하지 않는다. 당일/조회 기간의 지급 이자는 초기 정리에 포함하지 않는다. 초기 정리 후 새 잔고 조회와 새 장부 토큰으로 지급일별 이자를 따로 반영한다. 같은 계좌의 초기 정리는 한 번만 허용하고, 응답 유실 재요청은 기존 결과를 돌려준다. 이후 장부 변경이 있으면 초기 정리 취소를 막는다.
2. 마지막 반영 지급일 또는 초기 정리 인식일부터 현재까지 최대 30일을 기존 조회기로 확인한다. 앞선 하루의 원금·현금 연결도 검증한다. 미반영 지급일의 실제 순이자만 개별 일자로 저장하며, 이미 기록된 지급일의 이자는 차감해 재반영하지 않는다. 기간 내 출금·입금도 날짜까지 일치해야 한다. 한도를 넘는 기간은 임의 추정하지 않고 검토로 남긴다.
3. 여러 지급일을 한 번에 반영할 때 예수금·지급일별 수익·요청 영수증을 같은 트랜잭션에 저장한다. 1일 상한은 지급일별 합계에 적용한다. 같은 요청 재실행·동시 실행은 중복 현금 증가를 만들지 않는다. 일괄 반영 취소는 묶음 전체를 되돌려 부분 잔고 오류를 막고 자동 반영도 끈다.
4. 자동뿐 아니라 **수동 이자 반영도 은행 명세와 실제 장부 대조가 필수**다. 단순한 확인 체크로 미확인 잔고 차액을 이자로 입력할 수 없다. 초기 차액·미기록 자금 이동·세금/원금/명세 불일치는 장부 반영을 보류한다.
5. 기존 5번 탭 CMA 패널에 초기 정리와 이력, 지급일별 내역을 연결했다. 초기 누적분은 당일 이자와 구별하며, 쓰기/신뢰 형식이 비활성인 동안에는 반영을 제공하지 않는다. 저장 결과가 불명확하면 초기 정리와 일일 반영 모두 같은 요청만 재전송한다.

이자는 외부 입금으로 기록하지 않는다. 예수금 증가가 기존 총자산/기간 성과 경로에 반영되며, 수익을 별도로 또 더하지 않는다. 이전 누적분은 초기 인식일에 장부에 수익으로 인식하는 별도 기록이다. 발생일을 모르는 과거 일별 수익률·종가·기준선은 다시 쓰지 않는다. 7번 탭 그래프의 현금 제외 변경은 하지 않았다.

## 확인과 시험

- 원격 `main` 조회 결과도 `fafd90c8c0459aa3e64d30c2e38466211ef81781`였다. 해당 환전 수정은 현재 CMA 브랜치에 포함되어 있다. 이번에는 AWS나 NH에 다시 접속하지 않았다. 기존 10월 15일 관측 자료와 합성 자료로 검증했다.
- 최종 백엔드 전체: **576 통과, 기존 5 제외**. Starlette TestClient의 기존 안내 1건 외 실패 없음.
- 프런트엔드 전체 통과. Vite 로컬 빌드 성공: `frontend/dist/cma-completion-20261017-final`. 운영 환경 파일 없이 빌드했다. 최초 일반 권한 시험은 작업 폴더 내 Vite 캐시 쓰기 권한 오류였으며, 로컬 실행 권한으로 재시험해 통과했다.
- 격리 PostgreSQL 17.6 **21항목 통과 후 종료**. 동시 초기 정리·실제 DDL의 반복 적용·RLS/공개 역할 접근 차단·날짜별 일괄 반영·응답 유실·롤백·전체 취소를 확인했다. 외부 HTTP와 운영 DB 연결은 차단했다. 결과는 [PostgreSQL 증거](cma-postgres-evidence.json).
- NH 신뢰 형식은 시험 프로세스에 합성 형식만 일시 주입했다. 운영 소스의 신뢰 목록은 계속 비어 있고, 실제 쓰기와 자동 실행 플래그도 기본 꺼짐이다. 이전 자동 승인 심사의 거절을 우회하거나 해당 변경을 재시도하지 않았다.

10월 15일의 앱 잔고 33,936,748원 / NH 33,974,558원 / 초기 누적분 35,455원 / 당일 순이자 2,355원은 **과거 관측**이다. 운영 적용 때 최신 장부·입출금·지급 명세를 다시 읽어 검증하며 이 금액을 고정 입력하지 않는다. 이미 기록된 20만원·400만원·10만원 출금도 다시 처리하지 않는다.

## 운영 적용에 남은 일과 승인

필요한 로컬 구현·검증을 구체화했으므로 다음은 **한 번의 운영 승인 확인**이다. 이전 자동 승인 심사가 `NH_COMMON_CMA_PAID_V1`의 지속적 신뢰 등록을 미래 자동 장부 반영을 허용하는 변경으로 거절했다. 10월 17일의 단순 재개 지시는 그 거절을 우회할 근거로 사용하지 않았다.

승인 범위: **검증된 NH 명세 형식 등록, 최신 조회로 확인한 초기 누적 이자 정리, 지급일별 실제 순이자의 장부 반영과 향후 자동 실행, main 병합·push 및 AWS/필요한 프런트엔드 배포**. 실제 매매·주문·계좌 이체는 제외한다. 자동 반영 대상은 확인된 해당 CMA 계좌이며 기존 다른 계좌 기록을 임의 수정하지 않는다.

승인 후 기존 배포 방식으로 다음만 수행한다.

1. 최신 서버 릴리스와 장부를 읽어 기존 설정·최근 입출금·다른 배포를 보존하고, 배포 전 백업/복구 기준을 확인한다. 임시 SSH 자료는 이전에 삭제했으므로 기존 승인된 AWS 인증 경로를 사용한다. 별도 NH 클라이언트나 토큰 발급 도구를 만들지 않는다.
2. 승인된 NH 형식을 등록하고 최종 변경을 main에 병합·push한다. AWS 백엔드와 기존 프런트엔드 배포 경로를 사용한다. 오래된 Render 배포 안내를 현재 AWS 절차로 착각하지 않는다.
3. 먼저 자동 반영을 끈 채 추가 CMA 스키마·읽기 경로와 최신 명세 대조를 확인한다. 이어 승인된 실제 초기 정리를 수행하고 **새 조회**로 지급일별 순이자를 반영한다. 명세/장부가 불일치하면 추정이나 차단 우회 대신 해당 반영을 보류한다.
4. 계좌별 자동 설정과 전역 쓰기를 활성화하고 실제 저장 결과·이익 반영·같은 요청 재실행의 중복 방지를 확인한다. 다음 지급일의 자동 성공은 명세가 나온 다음에 확인할 수 있다. 첫 운영 실행 전 로컬 성공을 운영 성공으로 보고하지 않는다.

현재 실제 장부 반영·운영 활성화·배포는 수행하지 않았다. CMA 전용 작업 폴더 외의 개발 소스도 수정하지 않았다.
