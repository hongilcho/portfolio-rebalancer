## 사용 흐름

5번 매매 및 입출금 기록 → 기록 입력 → NH 알림 가져오기에 붙여넣는다.
일반 분배금 입금 안내와 퇴직연금 분배금 입금안내 두 형식을 지원한다.
여러 알림을 한 번에 붙이거나 반복해서 확인 목록에 추가한 후 함께 반영한다.
마스킹 계좌번호·등록 종목명을 하나로 확인할 수 없으면 직접 선택한다.

실수령액·입금일·배당 기준일·세전금액·세금합계를 구분한다.
세금이 제공되지 않은 메시지는 세금 0원으로 추정하지 않는다.
링크·고객명·안내문은 명령으로 취급하지 않으며, 링크 접속도 하지 않는다.
알림 원문은 서버에 저장하지 않고 필요한 구조화 필드와 지문만 저장한다.

## 회계 처리

- 실수령 원화만 예수금에 한 번 가산한다. 외부 투자자금 performance_flows를 만들지 않는다.
- 이미 실제 잔고에 포함된 배당은 ‘이미 잔고에 반영됨 · 기록만 저장’으로 등록한다.
- 배당 기준일은 배당락일로 치환하지 않는다.
- 같은 종목의 최근 14일 공시 후보가 하나뿐인 경우 연결 후보로 제시하고 최종 확인을 받는다.
- 연결한 배당은 기존 공시 계산액을 실수령액으로 교체한다. 계산액에 실제 입금을 더하지 않는다.
- 공시가 없거나 여러 후보라면 입금만 처리할 수 있다. 배당 손익은 기존 자동 계산을 유지하며 이를 안내한다.
- 늦은 공시는 5번 기록 조회의 해당 배당 상세에서 ‘배당 손익 연결’로 보완할 수 있다.
  이미 재투자했더라도 예수금·보유 수량·매입원가를 변경하지 않는다. 연결 전후 근거는 기존 요청 감사 기록에 보존한다.
- 기존 수동 배당 보정값은 우선한다. 수동 보정 종목에 실수령액을 겹쳐 반영하지 않는다.
- 재투자는 기존 매수로 입력한다. 기존 매입원가·수익률 분모·배당 적격 수량 규칙은 유지한다.
- 매도 실현손익 계산법 및 기존에 저장한 과거 평가·기간 성과 기록은 재작성하지 않는다.
  실제 수령액 교체는 현재 보유자산 평가와 이후 수집 기록에 적용된다.

## 무결성과 취소

포트폴리오·계좌 잠금과 기존 NH 배치 트랜잭션을 재사용한다.
같은 계좌·종목·기준일의 배당은 입금일·문자 공백·지문·중복 허용 체크를 바꿔도 재입금하지 못한다.
같은 공시 배당에 두 입금 기록을 연결할 수도 없다.
동일 요청 재전송은 기존 결과를 반환하며, 일부 행 실패는 전체 배치를 롤백한다.
예수금이 바뀌었거나 다른 포트폴리오의 계좌·종목이면 저장을 차단한다.
기존 잔고가 음수라도 양수 배당 입금 자체를 잔고 부족으로 막지 않는다.

취소는 기존 NH 알림 묶음 취소를 따른다. 후속 거래가 있으면 먼저 후속 거래부터 취소하도록 막고,
실행 가능한 취소는 이전 예수금·수량·원가를 복원한다. 기록은 삭제하지 않고 취소 이력을 남긴다.
5번 기록 조회의 현금 기록과 7번 배당 계산 상세에서 확인 근거를 표시한다.

## 조회·성능

실제 배당 확인 자료는 기존 보유잔고·대시보드 SQL 안에서 함께 읽는다.
종목마다 별도의 DB 왕복을 추가하지 않고 금융 값을 전역 캐시에 보관하지 않는다.
배당 확인 자료가 없는 기존 보유잔고 응답의 형태는 그대로 유지한다.
기존 공통 조회 무효화 경로가 NH 입금·취소·연결 후 다른 화면을 갱신한다.

## 스키마 및 배포 시 고려

새 테이블을 만들지 않는다. 기존 nh_notice_items.kind CHECK에 DIVIDEND만 추가한다.
기존 표의 RLS·권한·테이블 소유권과 금융 데이터는 변경하지 않는다.
기존 startup 마이그레이션 잠금 안에서 CHECK 변경이 한 번만 적용되며 합성 PostgreSQL에서 반복 적용을 확인했다.

기능 경계 nh_dividend_protocol=1을 확인하므로 구 백엔드에는 배당 저장을 보내지 않고 안내한다.
추후 승인받아 배포할 때는 DB 백업·지문을 먼저 확보하고, 백엔드 기능 확인 후 프런트엔드를 반영한다.
되돌릴 경우 이미 생긴 배당 기록과 확장된 CHECK를 삭제하거나 이전 CHECK로 축소하지 않는다.
구버전은 실수령액 연결을 표시하지 못할 수 있으므로 기존 기록을 보존한 상태에서 복귀 검증이 필요하다.
