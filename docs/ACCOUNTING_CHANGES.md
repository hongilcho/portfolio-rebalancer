# 자산 집계 및 거래 취소 기준

## 수익률과 총자산

개별 포트폴리오, 전체 요약, 종목별 합산, 가상자산과의 합산에 같은 기준을 적용합니다.

- 보유자산 매입원가: 현재 보유 수량에 해당하는 매입원가. 예수금 제외.
- 평가손익: 보유자산 평가액 − 보유자산 매입원가.
- 배당 포함 손익: 평가손익 + 보유자산의 세후 누적 배당.
- 보유자산 수익률: 배당 포함 손익 ÷ 보유자산 매입원가 × 100. 원가가 0이면 0%.
- 총자산: 보유자산 평가액 + 원화 예수금 + 달러 예수금 × 현재 환율.

배당은 손익에 반영하며 총자산에 다시 더하지 않습니다. 배당 지급 후 현금 잔고는
잔고 동기화 또는 사용자 입력으로 관리합니다. 총자산 계산만으로 배당 입금을 추정하지 않습니다.
이 수익률은 현재 보유 포지션 기준이며 청산 포지션의 실현손익을 포함한 생애 수익률,
시간가중 수익률 또는 입출금 기준 IRR은 아닙니다.

원화 카드는 원화 자산과 원화 예수금, 외화 카드는 미국 자산과 달러 예수금을 포함합니다.
가상자산 포함 상태는 원화 카드와 통합 집계에 동일하게 적용합니다. 고정된 시세·환율로
원화 순자산 + 외화 순자산 × 환율을 통합 순자산과 대사합니다.
API의 원화 표시는 원 단위, 달러 표시는 센트 단위 반올림을 하므로 표시값 대사에는
반올림 오차를 고려해야 합니다. 전체 수익률은 포트폴리오 수익률의 단순 평균이 아니라
전체 손익을 전체 보유원가로 나누어 계산합니다.

`grand_total.total_buy`와 포트폴리오별 `total_buy`는 예수금을 제외합니다.
`total_profit`과 `total_profit_pct`는 배당을 포함합니다. `eval_profit`과
`dividend_profit`으로 손익 구성도 제공합니다. 전체 종목 응답에는
`total_dividend_profit`, `total_dividend_profit_usd` 및 분산 내역별 배당 필드를 제공합니다.
주가 손익과 환차손익에는 배당을 섞지 않습니다.

## 거래 삭제

신규 거래는 `trade_history.cash_delta_krw`, `cash_delta_usd`에 실제 예수금 변동액을 기록합니다.
달러 원가 추적을 시작하지 않은 계좌의 달러 매수는 달러 예수금이 충분하면 달러를 차감하고, 부족하면 거래 전체 금액을 원화에서
차감하는 기존 결제 정책을 유지합니다. 달러 매도는 달러 잔고가 있으면 달러로, 없으면
원화로 입금합니다. 이 정책은 환전 주문이나 실제 증권사 체결을 실행하는 기능이 아닙니다.

달러 원가 추적을 시작한 계좌는 평균 취득환율로 매수 원가를 기록하고 달러가 부족하면
매수를 거부합니다. 매도대금은 달러로 입금하고 명시적인 수취기준환율로 원가를
평가합니다. 취소는 이후 환전·매매부터 역순으로 처리하며 전후 상태를 복원합니다.
자세한 기준은 [달러 원가 관리](USD_COST_LEDGER.md)를 참고하세요.

삭제는 기록된 현금 변동액을 역반영한 뒤 남은 거래 이력으로 수량·원가·매입환율을 재계산합니다.
`trade_sequence`는 같은 거래일의 신규 거래 순서를 보존합니다.
기존 거래의 실제 입력 순서는 알 수 없어 종전 ID 정렬을 유지합니다.
INIT는 잔고 스냅샷이며 현금 변동은 없습니다. 수동 배당 보정값과 최초 매수일은 보존합니다.
전량 취소된 잔고는 수량·원가를 0으로 유지해 부가 정보를 잃지 않습니다.

일괄 삭제는 하나의 트랜잭션입니다. 없는 ID, 중복 ID, 잔여 매도의 수량 부족,
취소에 필요한 현금 부족 또는 쓰기 오류가 발생하면 전체 변경을 롤백합니다.
계좌를 정렬된 순서로 잠근 뒤 거래를 처리합니다.

기존 BUY/SELL에는 실제 결제 통화를 복원할 정보가 없을 수 있습니다.
새 현금 변동 컬럼은 기존 거래에 대해 NULL로 남기며 임의로 채우지 않습니다.
이러한 거래의 삭제는 잔고 대사 전까지 거부합니다. 기존 INIT는 현금 변동 없이 취소할 수 있습니다.
이미 삭제된 과거 거래의 잔고 차이를 이번 변경으로 자동 보정하지 않습니다.

## 검증 환경

```powershell
python -m pytest -q -p no:cacheprovider
cd frontend
npm run test
npm run lint
npm run build
```

`tests/conftest.py`는 수집 전에 비밀 설정 파일 로딩을 끄고 운영 환경변수를 제거합니다.
실제 PostgreSQL 연결 및 requests/curl_cffi/소켓 네트워크 호출을 거부합니다.
Windows 이벤트 루프의 내부 socketpair 생성만 허용합니다. 앱 import에는 DB 초기화와
캐시 IO가 없으며, 실제 서버 lifespan 시작 시 DB 초기화 및 캐시 예열이 진행됩니다.

운영 DB 의존성이 있던 기존 테스트 5개는 명시적으로 건너뜁니다. 기본 pytest 실행을
운영 DB에 연결해 통과시키지 않습니다. 새 거래 회귀 테스트는 실제 앱 함수를
메모리 SQLite의 커밋/롤백과 연결해 검증합니다. 어댑터는 `%s`를 `?`로 바꾸고
`FOR UPDATE`를 제거하므로 PostgreSQL의 행 잠금·동시성·DDL 검증을 대신하지 않습니다.
전체 요약 및 HTTP 테스트의 시세·환율·배당·보유 데이터는 모두 합성 입력입니다.

프론트엔드 캐시는 계산식 버전을 구분하며 가상자산 포함/제외 결과를 별도로 보관합니다.
이전 범위의 늦은 응답이 현재 토글 결과를 덮어쓰지 않도록 요청 순서를 확인합니다.

## 배포 전 확인

실제 배포 SHA, Render/Vercel 연결 브랜치와 Auto-Deploy 설정은 각 대시보드에서 확인합니다.
이 문서 작성 시 운영 배포 또는 운영 DB 변경은 수행하지 않았습니다.

서버 시작 시 `init_db()`가 현금 변동 컬럼 2개와 BIGSERIAL `trade_sequence`를 추가합니다.
초기화에는 트랜잭션 단위 advisory lock을 사용하며, 최대 30초 동안 잠금을 기다립니다.
스키마 초기화 실패 시 서버 기동을 중단합니다. 운영 DB 백업과 기존 거래의
삭제 제한 안내를 준비하고, 계산식이 바뀐 API와 프론트엔드를 함께 배포합니다.
예전 프론트엔드 캐시를 복원하지 않도록 v2 키를 사용합니다.

[배포 준비 검증 기록](PREDEPLOY_VERIFICATION.md)에 정리했습니다.
