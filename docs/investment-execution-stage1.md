# 투자 실행 화면 첫 단계

계획서의 화면 검토 단계다. 실제 장부 연결이나 DB 변경은 아직 포함하지 않는다.

- 실행 화면: `frontend/src/components/Tab8Execution/ExecutionTab.jsx`
- 진행 표시: `frontend/src/utils/investmentProgress.js`
- 로컬 합성 미리보기: `/dev/investment-execution/index.html`
- 미리보기는 기존 TradeBatchForm과 NH 알림 파서를 사용한다. API 클라이언트를 가져오지 않으며 기록은 브라우저 메모리에서만 변경된다.
- 8번에서 결과를 입력하고 5번 예시 화면에서도 같은 초안·매매 폼을 확인할 수 있다. 실제 NH 전체 입력 화면의 분리·공통화는 화면 승인 후 다음 단계에서 진행한다.
- 상황 선택으로 입금 준비, 국내 매수, 부분 체결, 환전, VT 직접 입력, 전체 완료를 확인한다.
- 운영 App의 탭과 기존 장부 경로는 아직 변경하지 않았다. 화면 승인 뒤 저장 구조와 공통 입력 연결을 진행한다.

진행 표시에서는 확인된 실행 사실과 실제 장부 반영을 구분한다. 장부 반영 대기 결과는 완료로 계산하지 않는다. 이 표시 함수는 금융 거래 검증이나 실제 잔고 변경을 수행하지 않는다.

## 검증 결과

- 프런트엔드 테스트 162건 통과, lint와 기존 운영 빌드 통과.
- 합성 화면을 독립된 헤드리스 Chrome에서 320·390·430px와 데스크톱 1280px로 확인했고 가로 넘침이 없었다.
- 모바일 터치 이벤트로 결과 입력을 열고, 알림톡 파싱·5번과 8번 간 초안 유지·부분 체결·VT 직접 입력·입금·기존 기록 연결·투자 종료를 확인했다.
- 실제 휴대폰 기기에서의 검증은 별도다. 확인된 브라우저 검증은 모바일 크기 및 터치 이벤트 에뮬레이션이다.
- 실제 운영 DB·증권사 API·계좌 자료에는 접근하지 않았다. 기록 저장은 미리보기 메모리만 갱신하며 새로고침하면 초기화된다.

계획서의 다음 검토 시점은 사용자 화면 확인이다. 이후 실행 과정 저장과 공통 장부 연결을 개발한다.
