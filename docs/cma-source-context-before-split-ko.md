## 앱의 목적과 실제 사용 방식

개인·가계의 장기 자산배분과 적립식 투자, 계좌별 한도, 매매·환전·입출금 장부, 리밸런싱, 기간 성과를 관리한다. 월 약 두 번 투자하는 과정의 시간적·인지적 부담을 줄이는 것이 핵심이다. 시장 예측에 따른 단기 매매 프로그램으로 바꾸려는 요청이 아니다.

주요 계좌는 ISA·IRP·연금저축 같은 절세계좌이며 대부분 NH 나무증권에 있다. 배우자의 ISA는 예외다. VT·PDBC는 본인의 일반 해외주식 계좌에서 달러로 직접 매수한다. 절세계좌의 API 지원이 불충분하여 모든 계좌를 API로 동기화하거나 자동 매매하는 것을 전제할 수 없다.

실제 투자 순서:

1. 사용자 또는 배우자가 CMA에 외부 투자금을 입금한다.
2. 앱의 리밸런싱 전략에서 종목·계좌별 계획을 만든다.
3. 이미 각 계좌에 있는 예수금을 고려하여 부족한 자금만 이동한다.
4. 국내 ETF·금현물은 사용자가 증권사에서 거래한다.
5. 해외 계좌에 원화를 이동하고 사용자가 필요한 달러만 환전한다.
6. 미국장에 VT·PDBC를 매수하고 결과를 공통 장부에 기록한다.

현재 자동화 개발 목표는 마지막 해외 ETF 매수다. 입금·이체·환전 및 국내 거래는 수동으로 유지한다.

## 공통 장부와 입력 원칙

포트폴리오의 금융 장부는 하나다. 탭별 별도 잔고나 거래 장부를 만들지 않는다.

- 5번 기록 탭은 투자 회차와 무관한 일반 매매·입출금·환전·정정 입력을 자유롭게 지원한다.
- 주 입력 수단은 NH 알림톡 붙여넣기다. 여러 메시지를 초안에 누적한 뒤 확인하고 함께 저장한다. 배우자 ISA, 해외 체결 알림 지연 등에는 직접 입력이 필요하다.
- 8번 투자 실행에서는 새 실행 결과를 같은 공통 장부 처리로 저장하거나 5번의 기존 기록을 회차에 연결한다.
- 기존 기록 연결은 관계만 추가한다. 현금·수량·원가를 다시 움직이지 않는다. 8번의 새 매매는 5번 조회에도 나타나야 한다.
- 5번 입력이 8번의 선택된 작업이나 연결 확인 체크 때문에 막히면 안 된다. 초안은 5번과 회차·작업별 8번을 분리한다.
- 일반 장부 취소와 투자 연결 해제는 다르다. 연결 해제는 원거래를 유지한다.
- 기록·현금·보유 수량·원가 변경은 하나의 회계 트랜잭션으로 처리하고 저장 뒤 관련 탭을 갱신한다. 응답 유실 시 같은 요청 ID와 내용으로 저장 결과를 확인한다.
- 1번 등 현황 화면에서 직접 잔고·수량·평단을 덮어쓰는 방향은 중단했다. NH 자동 동기화도 덮어쓰기를 중단하고 대조 기능으로 바꾸었다. 현재 `backend/routers/sync.py`에서 이전 동기화는 410을 반환한다.
- 이 원칙은 금융 장부 변경에 관한 것이다. 승인된 시세 캐시·종가 성과 수집·작업 상태 저장까지 모든 DB 쓰기를 금지한다는 뜻은 아니다.

## 과거 문제가 알려주는 회귀 검증 항목

- 외부 입금을 기록했는데 실제 예수금에 반영되지 않아 환전이 불가능한 교착이 있었다. 입출금 기록·현금 반영 여부를 구분하고 재입력으로 이중 반영하지 않아야 한다.
- 달러 원가 추적 계좌를 직접 잔고 수정에서 차단하면서 정당한 입금·환전 경로도 막히면 안 된다.
- 성과 기준일 이전에 누락한 출금은 처리 불가능한 사건이 아니다. 과거 누락 정정으로 안내하고 현재 잔고와 과거 성과에 미칠 영향을 구분한다. 이미 반영된 출금인지 먼저 확인한다.
- NH 출금 안내에는 `출금가능금액`이 함께 올 수 있다. 실제 출금액과 잔고를 혼동하지 않는다.
- 내부 계좌 이동과 외부 가계 자금 출입을 구분한다. 포트폴리오 간 이동도 총가계 자산에서 새 수익이나 투자금으로 중복 계산하면 안 된다.
- 성과 갱신 큐 안에서 같은 큐에 작업을 넣고 기다리는 교착을 경험했다. 장부 저장 뒤 탭 갱신·성과 갱신의 호출 순서를 확인한다.
- 8번 투자 연결을 모든 5번 입력에 강제하여 자유 입력을 막던 UX는 거부되었다. 원래 문제의 재현과 해결을 완료 기준에 포함한다.

## 환전과 성과의 합의된 정의

- 현재까지의 보유 자산 환차손익은 기존 값을 인정하고 이후 달러 현금·환전 이벤트를 추적하는 방향을 선택했다. 과거 불완전한 거래로 전체 환율을 임의 재구성하지 않는다.
- 달러 잔액의 시작 평균 취득환율을 등록한 뒤 새 환전은 계좌별 달러 현금 이동평균 원가에 반영하고, VT·PDBC 매수에 사용한다.
- 앞으로 통합증거금 매수는 사용하지 않으려는 사용자 선호가 있다.
- 국내 배당은 앱의 원화 값과 증권사 값이 일치했던 사용 경험이 있다. 미국 ETF 배당의 실제 달러·환율·입금 방식은 당시 미확인이다. 조회된 배당을 예수금에 임의 합산하지 않는다.
- 개별·전체의 기본 지표는 배당 포함 보유자산 수익률이다. 예수금은 총자산에 포함하되 해당 수익률 분모에서는 제외한다. 기간 성과와 이 지표를 혼동하지 않는다.
- 종가 성과는 조회 순간 평가액과 다르다. 종가 수집·저장 작업과 기간 그래프가 개발되었으며 과거 모든 조회일의 평가액이 자동으로 존재한다고 가정하지 않는다.
- 사용자는 10월 5일 종가 기준으로 누적 손익 0원·수익률 0% 통일을 요청했다. 적용 범위·해당 포트폴리오의 실제 시작 기준과 기록은 코드·DB 증거로 확인한다.
- 특별한 외부 입출금이 없으면 기본적으로 없음을 가정하는 UX를 선택했다. 매일 확인 체크를 반복하게 만들지 않는다.

## 투자 계획과 회차

4번에서 리밸런싱 전략을 만든 다음 그 아래에 이름을 붙여 계획으로 저장한다. 계획 자체와 해당 계획을 실제 수행하는 투자 회차는 다르다. 투자 시작에 입력한 예정 추가 입금액은 금융 장부에 실제 입금을 기록한 것이 아니다.
