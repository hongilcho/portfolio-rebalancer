## 사용자 설명과 처리 기준

- 사용자가 오늘 CMA에서 외부로 200,000원을 인출했고 이미 장부에 기록했다고 설명했다. 현재 NH 조회 잔고와 앱 잔고의 차액은 이자라는 확인을 받았다. 실제 DB를 읽어 출금 기록이나 잔고를 재검증한 것은 아니다.
- 사용자 정정에 따라 상품 전환은 **저녁이지만 정확히 20시는 아니다**. 예수금이 0원이어도 MTS 출금가능금액은 전체 잔액을 표시한다고 확인했다. 실제 API의 CMA 잔액 항목과 전환/반환 시각은 미확인이다. 2026-10-15에 20시 기반 차단을 제거했으며 시간에 관계없이 조회된 현금·상품 상태로 판정한다. 원금이 상품으로 바뀌는 일을 출금/손실로 처리하지 않고, 상품에서 돌아오는 원금 전체를 이자/외부 입금으로 처리하지 않는다.
- 이자 후보는 **반환 후 확인된 현금 잔고 − 현재 장부 예수금**이다. 이미 반영한 출금/입금/이체를 다시 더하거나 빼지 않는다.
- 초기 누적 차액은 확인한 날짜에 누적 이자 수령액으로 기록한다. 과거 날짜별 발생액·금리·세금·미지급 이자는 추정하지 않는다.

예: 장부 5,000,000원에서 이미 출금 200,000원이 반영돼 4,800,000원이고 NH 반환 현금이 4,800,123원이면 **123원만** 이자로 반영한다. 예수금은 4,800,123원이 되고, 기존 외부 출금 −200,000원은 그대로 남는다. 기간 손익에는 123원이 수익으로 나타난다.

## 조회 결과 판정

이자 확정 기준에 기존 대조의 fallback 합계나 출금가능금액을 사용하지 않는다. `dca` 현금과 CMA 상품 `eal_amt`를 분리하고, 상품 수량을 원화로 간주하지 않는다.

- 특정 시각을 전환으로 간주하지 않는다. 예전 기록의 `NIGHT_TRANSITION` 표시 호환성은 유지하되 새 판정에서는 생성하지 않는다.
- 상품 잔고가 남음: `AWAITING_CASH_RETURN`, 반환 대기. 원금을 다시 수익으로 반영하지 않음.
- 현금 0원: `ZERO_UNVERIFIED`, 원금 소실/출금으로 확정하지 않음.
- 현재 예수금과 D+2 기준이 다름, 금액/목록 누락, 다른 자산 보유 또는 업무 응답 불명확: 검토 상태. 자동 반영하지 않음.
- 반환 현금보다 장부가 큼: 음수 이자로 차감하지 않고 실제 자금 이동/조회 기준을 확인하도록 중단.
- 당일 10분 이내 조회와 미리보기 이후 변경되지 않은 장부만 수동 반영 가능.

`drn_pbl_amt`는 `withdrawable_krw`로 별도 보존하고 5번 패널에서 참고값으로 표시한다. 예수금 0원·출금가능금액 전체 표시를 현금 반환이나 이자 확정으로 오해하지 않는다. `total_krw`는 확인된 현금+CMA 상품 평가액의 합계이며, 출금가능금액을 다시 더하지 않는다. 이 값이 실제 계좌 총평가액이라는 주장은 아니며 상품 잔액 필드의 실제 의미는 검증 전이다. 출금가능금액이 없는 과거 기록은 0원 대신 미확인으로 표시한다.

현재 인식하는 업무 완료 봉투는 `rsp_cd=00000`와 `rsp_msg=조회가 완료되었습니다.` 및 정상 잔고 블록을 함께 요구하는 **보수적인 준비 프로필**이다. 이것이 실제 NH CMA 잔고 API의 모든 성공 응답 형식이라는 주장은 아니다. 실제 응답의 봉투·현금/상품 금액 항목·CMA 상품 식별이 이 프로필과 맞는지 확인해야 하며, 맞지 않으면 실제 자료에 근거해 수정하고 로컬 시험 후 활성화한다. HTTP 200만 보고 금액을 자동 반영하지 않는다.

## 매일 확인과 이자 반영

앱 내부 실행기의 준비 일정은 한국 시간 **09:00·12:00·15:40**, 계좌당 하루 최대 3회다. 주말도 확인 대상으로 삼으며, 종가 성과 기록은 기존 KRX 거래일 정책을 따른다. 실행기를 재시작해도 DB의 슬롯 소비 기록을 사용해 같은 슬롯을 재호출하지 않는다. 지나간 슬롯을 한꺼번에 실행하지 않는다.

반환 시각은 추정하지 않는다. 현금 반환이 미확인이면 다음 슬롯에서 확인한다. 자동 반영은 **같은 날 동일한 현금 잔고·장부가 두 번 관찰된 경우**만 가능하다. 두 관찰은 1분 이상·4시간 이내이며, 한 번만 정상 응답이 오면 수동 검토 대상으로 남는다. 하루가 지나도 두 번째 확인이 없으면 자동 반영하지 않는다.

계좌별로 ‘매일 확인’만 켜면 검토만 수행한다. 자동 반영은 별도 opt-in, 자금 이동을 빠짐없이 장부에 기록한다는 확인, 사용자가 정한 1일 이자 상한이 필요하다. 반영 직전에 현재 설정을 다시 확인하며 상한 초과·설정 해제·장부 변경 때 반영하지 않는다. 한 계좌에 하루 한 이자 기록만 허용한다.

5번 탭의 새 패널에서 조회→차액 검토→이자 반영 및 최근 이력/상태를 확인할 수 있다. 미확인 저장 요청은 브라우저에 같은 요청으로 보존해 재송하고 새 요청을 만들지 않는다. 이자 취소는 이후 장부 변경이 없을 때만 가능하며, 취소 후 자동 반영은 해제하여 다음날 같은 차액을 자동으로 재계상하지 않는다.

## 성과 기록 시점

예수금에 이자를 더한 뒤 기존 다음 종가 평가에 포함되므로 총자산·기간 손익·금액가중 기간 수익률에 반영된다. 수익에 이자 금액을 다시 더하지 않는다. 과거 종가·시작 기준을 자동 수정하지 않는다.

이미 당일 종가가 기록되었다면 기존 7번 탭의 ‘오늘 종가 기록 재시도·장부 반영’을 명시적으로 실행해 갱신할 수 있다. 이자는 확인일에 기록하며 오래전에 쌓인 이자를 임의의 과거 날짜들로 나누지 않는다. 이는 과거 성과를 완전히 복원하는 기능이 아니다.

## 비활성 상태와 남은 운영 검증

기능 스위치 `CMA_INTEREST_ENABLED`는 기본 **0**이다. 이 상태에서는 CMA API의 조회/반영/설정 동작을 차단하고 스케줄러 스레드를 만들지 않으며 CMA 테이블도 초기화하지 않는다. `.env`, AWS 설정, 실제 DB 및 서버 상태를 변경하지 않았다.

별도 승인 후 실제 활성화 전에 필요한 일:

1. 기존 AWS 앱의 NH 연결을 재사용하여 실제 CMA 응답의 업무 봉투·금액 항목·현금 반환 상태를 읽기 전용으로 확인한다. 이미 동작하는 인증 구조를 별도 발급 절차로 대체하지 않는다.
2. 별도 격리 PostgreSQL에서 새 DDL 재실행·동시 슬롯 소비/수익 반영과 권한을 검증한다. **후속 승인에 따라 완료:** 기존 검증 폴더에서 PostgreSQL 17.6 실행 파일을 찾아 독립 합성 클러스터에서 13항목을 검증한 뒤 종료했다. [후속 결과](cma-readonly-postgres-validation-ko.md)를 참조한다.
3. DB 백업과 준비된 `portfolio_cma` 비공개 스키마 적용/기능 활성화를 검토한다. 실제 반영 전 선택한 CMA 계좌의 자금 이동·초기 누적 차액을 대조한다.
4. 처음에는 매일 확인만 활성화해 반환 패턴을 관찰한 뒤, 자동 반영 상한과 정책을 확정한다. 운영 적용·조회·실제 장부 쓰기는 이번 승인이 아니다.

비공개 테이블은 Data API 역할에 권한을 주지 않고 RLS를 사용한다. 기존 사용자/서비스 권한을 넓히지 않는다. Supabase 고유 기능이나 외부 서비스 설정은 변경하지 않았으며, 외부 문서 조회를 요구하는 스킬 지침보다 사용자의 외부 호출 금지를 우선했다.

## 로컬 검증

전용 시험은 가짜 NH 응답과 메모리 SQLite 트랜잭션을 사용한다. 계좌/포트폴리오 범위, 20만원 출금 중복 처리 방지, 야간 0원/상품 전환, 소수 금액, 두 번 확인, 슬롯 소비, 자동 상한/해제, 장부 변경, 중복 요청, 실패 rollback, 취소, 외부 입출금 불변과 양의 기간 손익을 검증한다. SQLite 시험은 PostgreSQL 동시 행 잠금을 실증하지 않는다.

전체 백엔드 및 프런트엔드 최종 결과와 보존 대조는 [최소 요약](cma-interest-local-evidence.json)에 기록한다. 프런트엔드 전체 193개 통과 및 격리 빌드 성공. 새 CMA 화면/계산 시험 7개 통과. 5번 탭 패널 추가에 해당하는 두 화면 해시만 검토 후 갱신했고, 나머지 기존 화면과 7번 그래프 시험은 그대로 통과했다.

최종 백엔드 전체 **1235 passed, 5 skipped**, 기존 Starlette 경고 1건. 새 CMA 백엔드 시험은 **59 passed**다. 기존 보존 기준 **443개** 파일을 대조해 의도적으로 변경한 연결/시험/맥락 8개를 제외한 **435개**의 해시가 동일함을 확인했다. 기존 자동매수 미커밋 파일·배포 자료·그래프와 성과 계산 소스를 보존했고 Git 커밋/push는 하지 않았다.
