# 투자 회차와 공통 장부 입력 흐름

## 사용 흐름

- 5번 탭은 투자 회차와 무관한 일반 장부 입력·조회·취소 화면이다. 8번의 연결 상태가 저장 조건에 전달되지 않는다.
- 8번 탭의 **새 체결 내역 입력**은 선택한 작업의 계좌·종목을 채우고 실제 수량·단가·일자를 입력받는다. 저장 버튼을 누르면 기존 공통 장부 API로 기록하고 해당 회차에 같은 트랜잭션으로 연결한다.
- **기록한 거래 가져오기**는 5번에서 저장한 거래 중 연결 가능한 거래를 선택하는 기능이다. 연결만 추가하며 예수금·보유 수량·원가를 다시 변경하지 않는다.
- 8번의 새 거래도 5번 기록조회에 표시된다. 5번에서 거래를 취소하면 8번 실적에도 취소가 반영된다. 8번의 연결 해제는 원거래를 유지한다.
- 가져오기 후보는 현재 작업과 계좌·종목·통화·방향이 맞아야 한다. 매매는 저장 계획 이후 등록된 거래, 자금 준비 기록은 투자 시작 이후 실제 잔고에 반영된 기록만 후보가 된다. 다른 작업에 이미 연결된 기록·취소 기록은 제외한다.

## 화면과 초안

연결 확인 체크박스를 제거했다. 작업 입력 화면은 해당 작업에 필요한 입력만 제공한다. 수동 체결 입력의 계좌·종목은 미리 채우고 수량·단가는 사용자가 실제 체결값을 입력한다. 저장 직전에 체결 목록과 예수금 변화를 보여준다.

5번과 8번은 같은 장부 처리 코드를 사용하지만 입력 초안은 분리한다. 8번 초안은 회차·작업별 저장소에 보관한다. 5번 초안과 서로 덮어쓰거나 자동 연결하지 않는다. 미확정 저장 요청은 원래 요청 ID·내용·연결 정보를 보존한다. 응답 손실 후 완료 작업으로 바뀌더라도 8번의 **저장 결과 확인**에서 동일 요청으로 결과를 확인할 수 있다.

## 검증

운영 DB·API·실제 자산에는 접근하지 않았다. 로컬 PostgreSQL 합성 DB와 외부 요청을 차단한 Chrome에서 다음을 검증했다.

- 8번 입력을 남겨둔 상태에서 5번의 독립 매수 저장 및 초안 보존.
- 5번 거래 가져오기 전후 장부 건수·예수금 불변, 투자 실적 증가.
- 8번 신규 체결이 5번 상세 조회에 표시됨.
- 환전·미국 ETF 매수와 평균 취득환율 보존.
- 저장 완료 후 응답 손실·새로고침·동일 요청 재시도 시 중복 거래 없음.
- 기존 거래 연결·실제 취소 후 남은 수량 재계산, 투자 종료 후 장부 유지.
- 포트폴리오 변경 및 구버전 백엔드에서 일반 5번 입력 유지.
- 320/390/430/1280px 화면의 가로 넘침 없음.

프런트엔드 회귀 테스트 177건, 최종 변경 관련 테스트 18건, 프로덕션 빌드와 정적 검사를 통과했다. Chrome 통합 검증은 9개 그룹을 통과했다. 실제 휴대폰과 운영 배포는 별도 검증 대상이다.

## 반영 범위

운영 DB 스키마·보안 설정과 백엔드 장부 API는 변경하지 않는다. 기존 `codex/investment-execution` 브랜치에서 개발했고, main 병합·origin push·운영 배포는 사용자 검토 후 진행한다.

## 수동 입금 저장 후 복귀

수동 외부 입출금은 성과 저장 큐 안에서 장부를 저장하고, 자산·투자 진행을 갱신한 뒤 같은 큐 안에서 성과를 갱신한다. 공통 후처리가 같은 큐에 새 작업을 넣고 기다리면 현재 작업이 끝나지 않는 교착이 발생하므로, 이 경로에서는 성과 갱신을 수동 입출금 패널에 맡긴다. 다른 입력 경로는 기존 성과 갱신을 유지한다.

저장이 완료되면 투자 입력 화면을 닫고 진행 화면으로 복귀한다. 이전 버전에서 이미 저장 후 멈춘 경우 새로고침하여 기존 기록을 조회한다. 입금을 다시 등록하지 않는다.

## 체결 입력 참고 단가

8번 투자 작업에서 새 수동 체결 입력을 열면 국내 종목은 앱의 원화 시세, 미국 종목은 달러 시세를 초기 단가로 채운다. 달러 시세가 없으면 원화 평가 시세를 현재 앱 환율로 환산하고, 유효한 시세가 없으면 작업의 저장된 계획 단가를 사용한다. 모두 참고값이며 실제 체결 단가는 사용자가 수정한다.

기존 입력 단가·알림 파싱 단가·미확정 저장 요청은 덮어쓰지 않는다. 초기 입력의 빈 단가만 채우며 가격 갱신으로 사용자의 체결값을 바꾸지 않는다. 수량은 사용자가 입력한다. 장부 쓰기·예수금·환전 원가 계산 방식은 변경하지 않는다.
