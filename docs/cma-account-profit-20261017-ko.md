# CMA 누적 세후 이자와 계좌 총손익

사용자 승인에 따라 CMA 전용 브랜치에서 기존 변경을 보존하면서 계좌 UI의 이자 표시를 추가했다. 실제 매매, 이자 재기장, 잔고 보정은 수행하지 않는다.

## 표시와 계산

- 계좌 화면에 **CMA 누적 세후 이자**를 별도로 표시한다. 취소되지 않은 초기 누적 이자와 지급일별 순이자를 합산한다. 최근 이력 30개 표시 제한과 무관하게 전체 활성 기록을 합산한다.
- 계좌 총손익 = 보유자산 평가손익 + 세후 배당 + CMA 누적 세후 이자. 포트폴리오 ID와 계좌 ID를 모두 대조하고, 취소 건과 미지급 평가분은 제외한다.
- 예수금과 계좌 총자산에는 이자를 다시 더하지 않는다. 잔고와 이자 기록을 동일한 SQL 스냅샷에서 읽어 표시한다. 기존 장부 쓰기·NH 조회·자동 이자 정책은 수정하지 않는다.
- 예금 제외 모드에서도 CMA 이자와 배당을 유지한다. 총손익이 정확히 0원이 되는 경우에도 평가손실로 잘못 대체하지 않는다.
- 기존 수익률은 보유자산 매입원가 기준으로 유지하고 CMA 계좌에는 **보유자산 수익률**로 구분한다. 현금만 있는 CMA 계좌는 해당 수익률을 `—`로 표시한다. CMA 이자를 주식 매입원가로 나누어 수익률을 만들지 않는다.
- 포트폴리오 보유자산 KPI 및 기간 성과 그래프의 계산 기준은 유지한다. 이번 변경은 계좌별 총손익과 별도 이자 표시다.

## 시험

- 백엔드 전체: **587 통과, 기존 5 제외**. 기존 Starlette 경고 1건.
- 프런트 전체 시험 및 Vite production 빌드 통과. 새 SSR 시험으로 실제 계좌 컴포넌트의 별도 이자·총손익·수익률 구분·현금 불변을 확인했다.
- 격리 PostgreSQL 17.6: **22항목 통과 후 종료**. 실제 overview 쿼리가 초기/일일 이자와 취소를 반영하고 반복 조회로 현금이 늘지 않는 것을 확인했다. 로컬 시험의 외부 연결과 운영 DB 쓰기는 차단했다. 상세 결과는 `cma-postgres-evidence.json`.
