# 계좌별 달러 취득원가와 환전 기록

## 적용 기준

기존 VT/PDBC 등 미국 자산의 수량·원화 원가·달러 원가를 현재 기준으로 인정합니다.
과거 환전이나 통합증거금 결제를 재구성하지 않습니다. 계좌별 추적 시작 시점에
현재 달러 예수금과 사용자가 입력한 마지막 환전환율을 시작 원가로 등록합니다.
기존 보유분의 환차손익을 이 환율로 다시 계산하지 않습니다.

추적은 계좌마다 명시적으로 시작합니다. 시작하지 않은 계좌는 기존 거래 정책을
유지하며, 달러 부족 시 원화 결제가 허용되는 종전 동작도 유지합니다.
추적을 시작한 계좌의 미국 자산 거래는 달러 단가로만 입력하며, 통합증거금 결제를
추정하지 않습니다. 달러가 부족하면 매수를 거부합니다.

## 사용 순서

1. 실제 계좌의 원화·달러 예수금을 앱 잔액과 맞춥니다.
2. `4. 매매 기록 → 달러 원가·환전 관리`에서 계좌를 선택합니다.
3. 시작 기준일시와 마지막 환전환율을 입력하고 `시작 기준 등록`을 누릅니다.
   현재 달러 잔액이 시작 원가에 반영되며 예수금이나 기존 종목 원가는 바뀌지 않습니다.
4. 이후 실제 환전을 하면 일시, 수령 달러, 실제 원화 지출액을 등록합니다.
   환전 비용이 있다면 실제 원화 지출 총액에 포함합니다.
5. VT/PDBC 등을 매수하면 입력창에 계좌 평균 취득환율이 표시됩니다.
   서버가 같은 환율을 적용하므로 매수창에서 임의의 환율로 바꿀 수 없습니다.

환전 기록은 실제 현금을 이동시킵니다. 환전 후 잔액을 먼저 동기화하거나 수동 입력한 뒤
같은 환전을 다시 등록하면 중복 반영됩니다. 가급적 환전 등록 → 매매 등록 → 잔고 확인
순서로 관리하세요. 과거 날짜를 삽입하려면 그 이후 기록을 최근 순서부터 취소하고
날짜 순서로 다시 입력합니다. 같은 날짜는 등록 순서가 계산 순서입니다.
매매 기록에는 거래일만 있으므로 실제 체결 시각을 만들어 넣지 않습니다.

## 계산과 기록

달러 잔액을 U, 원화 취득원가를 C라고 할 때 평균 취득환율은 C/U입니다.

- 원화→달러 환전: 원화 예수금에서 실제 지출액 K를 차감하고 달러 D를 더합니다.
  새 평균환율은 `(C + K) / (U + D)`입니다.
- 달러 매수: `수량 × 달러 단가`만큼 달러를 차감하고 그 금액 × 기존 평균환율을
  달러 현금 원가에서 차감합니다. 남은 달러의 평균환율은 유지됩니다.
  기존 종목의 원화·달러 원가에 새 매수 원가를 각각 합산해 평단가와 매입환율을 구합니다.
- 달러 매도: 매도대금을 달러로 입금합니다. **매도대금 수취기준환율**로 새 달러의
  원가를 평가합니다. 입력창 기본값은 현재 환율이며 사용자가 수정할 수 있습니다.
  이는 원가 평가 기준이고 실제 환전환율이나 환전 이벤트가 아닙니다.
- 달러→원화 환전: 달러를 기존 평균원가로 차감하고 실제 원화 수령액을 예수금에 더합니다.
- 확인된 달러 입금: 실제 입금액과 명시적인 원가 기준환율을 입력합니다.
  달러 출금은 기존 평균원가를 유지하며 차감합니다.
- 계좌 간 달러 이동: 양쪽 계좌에 출금·입금을 기록하고 출금 계좌의 평균원가를
  입금 기준환율로 사용합니다. 두 계좌를 동시에 처리하는 이체 기능은 포함하지 않습니다.

예: 시작 $400 × 1,300원 = 520,000원, 추가 환전 $600에 840,000원 지출 시
평균환율은 1,360원입니다. $700을 매수에 쓰면 남은 $300의 원가는 408,000원입니다.
기존 VT 5주 × $100 × 1,250원의 원가는 유지한 채 새 7주 원가 952,000원을 합쳐
12주의 원화 원가는 1,577,000원이 됩니다.

주식 매매 수수료 입력은 기존 기능과 같습니다. 별도의 매매 수수료·세금 현금 항목은
추가하지 않았으므로 증권사 실결제액과 차이가 발생하면 확인 후 대사해야 합니다.
현금의 실현 환차손익을 별도 종합 수익률에 추가하는 기능도 포함하지 않습니다.

## 배당과 잔고 대사

시세·배당 API의 추정 배당으로 실제 달러 입금을 생성하지 않습니다.
원화로만 알려진 배당을 달러로 역산하거나 환율을 추정하지 않습니다.
실제 USD 입금액과 원가 기준이 확인된 경우에만 달러 입금으로 등록합니다.

증권사 동기화와 계좌 설정의 수동 잔액 변경은 실제 현금 잔액에 반영됩니다.
그 결과 원장과 달러 잔액이 다르면 경고를 표시하고 달러 거래·환전을 차단합니다.
`현재 잔고 원가 대사`에서 **현재 달러 전체의 확인한 평균 취득환율**을 등록하면
원가 기준을 다시 맞춥니다. 대사는 예수금이나 보유 종목 원가를 변경하지 않습니다.
기존 이벤트와 대사 전후 상태는 그대로 남습니다. 입금 원가를 모르면 새로운
기준을 사용한다는 사실과 근거를 메모에 남겨야 하며 정확한 과거 원가로 간주하지 않습니다.

추적 계좌의 직접 보유잔고 저장은 거부합니다. 종목 변경은 매매 기록을 사용하세요.
증권사 동기화는 미국 자산 수량이 기록과 일치할 때 원가를 유지합니다.
수량이 다르면 전체 동기화를 롤백하고 누락 거래 입력을 요청합니다.
예수금은 총자산에만 포함하며 보유자산 수익률 분모에서 제외하는 기존 기준을 유지합니다.

## 취소와 데이터 보존

계좌의 가장 최근 유효 이벤트부터 취소할 수 있습니다. 이후 환전이 남은 상태에서
그 이전 매수를 삭제할 수 없습니다. 여러 매매를 선택한 취소는 같은 트랜잭션에서
역순으로 처리하며 하나라도 불가능하면 모두 롤백합니다.

취소는 저장된 전후 상태로 원가를 복원합니다. 기존 보유분의 최초 매수일과
수동 배당 보정값은 유지합니다. 취소된 환전·매매 이력은 삭제하지 않으며
연결된 거래 ID도 보존합니다. 추적 시작 이전 미국 자산 거래는 시작 원가의
기준이므로 추적 중에는 삭제를 거부합니다.

- `usd_cash_state`: 계좌별 달러 잔액, 원화 원가, 마지막 처리일.
- `usd_cash_events`: 이벤트 순서, 실제 일시/거래일, 금액·환율, 현금 변동,
  전후 원가와 보유 상태, 메모, 취소 시각, 매매 연결.
- 시작 이벤트에는 당시 미국 자산 보유내역도 보존합니다.
- 현금 원가는 `NUMERIC(28,10)`와 Python Decimal로 계산합니다.
  기존 REAL 원가·거래 컬럼 일부는 기존 API 값을 유지하며 DOUBLE PRECISION으로 넓힙니다.
- CSV 백업에 두 원장 파일과 전후 상태 JSON, 취소 기록을 함께 포함합니다.
  CSV는 조회·보존용이며 자동 복원 도구가 아닙니다. DB 전체 복구는 pg_dump 백업을 사용합니다.

계좌 또는 포트폴리오 삭제 시 해당 원장도 종전 삭제 정책에 따라 함께 삭제됩니다.
원장에 연결된 자산 삭제는 외래키로 보호합니다. 삭제 전 별도 백업이 필요합니다.

## 검증 및 배포

```powershell
python -m pytest -q -p no:cacheprovider
cd frontend
npm test
npm run lint
npm run build
```

별도로 준비된 **로컬** PostgreSQL에서:

```powershell
python scripts/verify_usd_ledger.py
python scripts/local_ui_preview.py --port 8554 --usd-ledger
```

위 스크립트는 `backups/local_validation/local_connection.json`의
127.0.0.1:55437 전용 DB에만 접속하며 실행마다 새 검증 DB를 만듭니다.
실제 PostgreSQL 검증은 동시 매수·취소, 원장 저장 실패 롤백, 잔고 동기화의
원가 보존, 대사, 매도대금·취소를 포함합니다. 일반 pytest는 운영 DB와 네트워크를 차단합니다.

배포 시 새 테이블 생성과 자료형 변경이 `init_db()`에서 수행됩니다.
운영 반영 전에 DB 전체 백업을 확보해야 하며 백엔드를 먼저 반영해야 새 API가
동작합니다. 기능 브랜치의 Vercel Preview가 운영 백엔드를 참조하는 상태에서는
검증용 환전·매매를 입력하지 마세요. 개발 검증은 고정 시세와 가상 잔액을 가진
로컬 환경에서 수행합니다.
