# 투자 실행 3단계: 실제 화면과 공통 입력 연결

개발 브랜치: codex/investment-execution. 운영 DB·API·실제 자산 및 인증정보에 접근하지 않았다. main 병합·push·배포는 수행하지 않았다.

## 구현 내용

- 8번 투자 실행 탭을 실제 앱에 연결했다. 4번 저장 계획에서 준비 화면을 열며, 기존 예수금과 앞으로 추가 입금할 금액을 구분한다. 준비 확인 후에만 투자 과정을 생성한다.
- 다음 접속에서 진행 중인 투자와 남은 작업을 조회한다. 지난 투자와 종료 당시 보고서를 따로 볼 수 있다.
- 5번과 8번은 동일한 HistoryTab 인스턴스와 장부 API를 사용한다. 탭 이동 때 NH 문자·수동 입력을 보존하며, 투자 작업 연결에는 사용자의 별도 확인이 필요하다.
- NH 알림톡을 여러 번 가져와 저장할 수 있다. 부분 체결의 실제 수량을 합산하며, 계획과 다른 계좌·종목·방향은 자동 연결하지 않는다.
- 계좌번호가 없는 알림은 현재 작업의 계좌를 제안하고 경고를 표시한다. 내부 이체의 출발·도착 계좌는 명시적으로 설정한다.
- 원화 내부 이체 수동 입력은 기존 NH 장부 처리 경로를 재사용한다. 절세계좌는 출발 계좌 후보에서 제외한다. 실제 은행 이체를 실행하는 기능은 아니다.
- VT 등 해외 매매는 기존 수동 입력과 달러 원가 처리를 사용한다. 계좌·종목 채우기 버튼은 미완성 입력을 덮어쓰지 않으며 실제 수량·단가는 사용자가 입력한다.
- 연결 후보는 서버에서 제한 조회한다. 기존 기록 연결·해제는 매매와 잔고를 다시 생성하거나 취소하지 않는다.
- 목표 변경, 중단·재개, 전체·부분 종료를 화면에 연결했다. 실제 기록 취소·정정은 5번으로 안내하며 정정 폼의 상태도 보존한다.
- 저장 후 자산·달러 원가·기록·성과·투자 진행을 갱신한다. 저장 중 화면/포트폴리오 변경을 막고 결과가 불확실한 요청은 원래 내용 그대로 재확인한다.
- 구버전 서버에는 투자 연결이 포함된 금융 요청을 보내지 않는다. 연결을 빼고 재전송하지 않으며, 기존 5번의 독립 기록 입력은 유지한다.
- 첫 대시보드 진입 때 투자 실행 API를 추가 호출하지 않는다. 투자 화면과 기존 기록 폼은 필요할 때 로드한다.

새 금융 계산식이나 별도 잔고 변경 경로를 만들지 않았다. 거래·환전 원가 및 성과 계산은 기존 서버 처리 경로를 사용한다. 신규 DB 구조와 보안은 2단계 결과를 유지한다.

## 검증 결과

- 프런트엔드 테스트 173건 통과. 연결 확인, 일치/모호/제외 작업, 내부 이체 양쪽 알림, 구버전 요청 차단, 새 화면 초기 진입 및 공통 폼을 검증했다.
- 백엔드 pytest 358건 통과, 기존 외부 DB 의존 테스트 5건 제외.
- 최종 빌드와 lint 통과. 기존 화면 회귀 기준은 수동 계좌 이체 선택 항목이 추가된 5번 두 경우만 명시적으로 갱신했다.
- headless Chrome과 127.0.0.1 전용 PostgreSQL 합성 DB로 실제 화면과 저장을 검증했다.
  - 저장 계획에서 시작, 준비/시작의 장부 불변, 새로고침 후 한 투자 재개.
  - 원화 이체 2건, 국내 ETF 7주와 13주 반복 입력·합산.
  - 5번↔8번 이동 때 붙여넣은 문자 보존.
  - 기존 100달러에 400달러 환전 후 VT 5주 입력. 달러 현금과 기존 보유의 취득환율 가중평균 보존.
  - 구버전 백엔드 모의 응답에서는 장부 요청 미전송. 연결 정보를 보존한 같은 요청 재시도 후 거래 1회 반영.
  - 중단·재개·목표 변경·기존 이체/매매 연결에서 장부 불변.
  - 원본 매매 취소 후 보유·예수금 복구와 남은 작업 표시, 사유 있는 부분 종료.
  - 320/390/430/1280px 화면의 가로 넘침 없음, 터치 이벤트로 공통 입력 열기.
- 화면 검증용 Chrome은 별도 프로필과 외부 도메인 차단을 사용했다. 외부 글꼴 요청 실패는 합성 검증의 네트워크 차단 결과다.

실제 휴대폰, 실제 증권사 알림/주문 응답, 운영 DB·배포 환경은 이번 단계에서 검증하지 않았다. headless 터치 이벤트 확인을 실제 기기의 터치 검증과 동일하게 보지 않는다.

## 로컬 검토와 다음 단계

실제 합성 앱은 http://127.0.0.1:5196/ 이며 검증 전용 비밀번호는 ui-test-only다. 합성 예시 투자에는 국내 매수 3주 중 1주가 기록되어 있다. 8번에서 이어가기·입력·지난 투자 보기 등을 확인할 수 있다. 화면 캡처 모음은 해당 서버의 /node_modules/.cache/investment-execution-live/review.html 에 있다.

다음은 4단계 최종 검증·운영 반영 준비다. 실제 연결 역할의 최초 스키마 생성 권한, 최신 백업/복구와 적용 순서, 양쪽 배포 버전, 정상 기능 및 비인가 접근 차단 확인이 필요하다. 사용자 승인 전에는 main 병합·push·운영 반영을 하지 않는다. 기존 코드로 되돌려도 추가 비공개 테이블과 실제 장부 기록을 삭제하지 않는 롤백 방침을 유지한다.
