# 실현손익 가시성·기간 보고서 개선

- 브랜치: `codex/realized-profit-report`, 기준 main: `7833284`.
- 완료된 CMA 작업 폴더를 재사용하되 별도 브랜치에서 개발. 다른 작업과 운영 DB는 변경하지 않음.

## 화면 흐름

1. 1번 현황의 기존 비중 괴리율·KPI 아래에 보유분 평가손익, 기록 범위 누적 매도손익(비용 전), 현재 보유종목 배당을 분리 표시.
2. 최근 매도 최대 3건은 기존 매매 계산 결과의 확정 순손익 → 예상 순손익 → 비용 전 손익 순서로 보여주며 기준을 명시. 예수금·총자산에 금액을 재합산하지 않음.
3. 실현손익 보고서 버튼으로 7번 해당 위치로 이동.
4. 보고서는 이번 달·올해·전체 기록 빠른 선택과 상세 날짜·계좌·종목 필터를 지원. 매도별·월별·연도별·계좌별·종목별로 조회 결과를 묶음.
5. 비용 전 합계와 확인 완료분 순손익을 분리. 모든 거래에서 확정/추정 순손익이 가능한 경우에만 예상 총계를 표시. 원가·비용 미확인 값을 0원으로 바꾸거나, 비용 전/후 금액을 혼합한 총계를 만들지 않음.
6. 전량 매도 완료·전체 보유기간은 기존처럼 전체 기간 이력을 표시. 기간 필터가 매도 원가 계산에 사용되는 과거 매수를 잘라내지 않음.
7. 7번에서 보유손익 그래프·실현 매도손익 보고서·기준일 이후 기간 운용성과의 의미를 구분하고 서로 이동. 보유 그래프나 기간 성과의 계산식·분모·저장 기록은 변경하지 않음.

## 백엔드와 데이터 보존

- `build_dashboard_summary`가 이미 계산한 결과를 한 번 재사용해 `realized_recent_sales`만 추가. DB·시세 조회는 추가하지 않음.
- 기존 `realized_summary`와 평가 응답 필드, 원가·수수료·이자·배당 계산은 그대로 유지.
- 최근 매도에는 계좌 별칭·종목명과 기존 계산 결과만 포함. 계좌번호와 새 쓰기 API는 추가하지 않음.
- 구버전 백엔드에서 새 선택 필드가 없으면 최근 매도 목록만 생략. 기존 누적 요약과 상세 보고서는 계속 동작.
- 스키마·마이그레이션·운영 설정 변경 없음. 승인 후 출시 시 프런트엔드와 AWS 읽기 API 배포가 필요함.
