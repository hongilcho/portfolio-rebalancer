## 사용 흐름

1. 계좌 정보 수정에서 한국상장 상품·미국상장 상품·금현물 요율과 적용 시작일을 설정한다. 금현물은 수수료 부가세 포함 여부를 선택한다. 공란은 미설정이고, 0%는 명시적인 무수수료다. 같은 계좌의 과거 요율 이력을 보존한다. 미국 멤버십 요율은 메모로 표시하며 임의로 만료시키지 않는다.
2. NH 체결 알림, 5번 수동 입력, 8번 투자 실행의 공통 매매 저장 경로에서 자동 계산한다. 명시적으로 확인한 실제 비용은 자동 계산보다 우선한다. 자동 계산은 예상 비용으로 기록하고 확정 순손익에 섞지 않는다. 원가가 충분한 경우 수수료를 반영한 예상 순손익은 별도로 보여준다. 매도 세금 등 미확인 비용은 확정된 0으로 처리하지 않는다.
3. 매수는 대금과 비용을 차감하고 매도는 비용을 뺀 금액을 반영한다. 거래 취소는 당시 저장한 비용을 되돌린다. 미국주식 비용은 달러 예수금과 달러 현금 원가를 같은 트랜잭션에서 갱신한다. 원래 체결단가·수량은 변경하지 않는다.
4. 4번 리밸런싱에 예상 수수료와 미설정 건수를 표시한다. 8번 자금 준비에서는 수수료를 별도 금액으로 포함하며 기존 가격·환율 여유율과 구분한다.
5. 가끔 5번의 '예수금 차이 정산'을 열어 계좌·통화·실제 잔고를 선택하고 차이 확인 후 반영한다. 실제 거래비용으로 확인한 차액과 원인 미확인/반올림 차이를 구분한다. 미확인 차이를 수수료로 확정하거나 외부 투자자금 입출금으로 만들지 않는다.

## 정확도와 보존 원칙

- 기본 수수료 계산은 Decimal 및 원화 1원/미국 달러 0.01달러 단위 절사다. 프런트엔드 미리보기는 정수 연산을 사용하고 서버가 최종 결정한다. 증권사의 내부 합산·거래소별 요율·부분 체결 및 평균단가 표시에 따른 잔돈 차이를 완전히 복제한다고 가정하지 않는다.
- 기존 매매대금 계산의 소수 정밀도는 변경하지 않는다. 따라서 평균 체결단가 곱셈에서 발생하는 센트 미만 잔액도 정산 대상이 될 수 있다. 비교할 때는 국내 D+2 등 같은 결제 기준의 잔고를 사용한다.
- 예상 수수료 때문에 실제 매매 기록을 못 넣는 상황을 피한다. 매매대금 반영 후 예상 비용을 충당하지 못하면 비용을 DEFERRED로 보존하고 예수금을 음수로 만들지 않는다. 기록 조회에 미차감 예상 비용을 표시한다. 사용자는 실제 잔고 대조 때 비용/잔고 차이를 정산할 수 있다. 실제 확인 비용의 부족은 기존 검증을 유지한다.
- 누적 정산은 오늘의 현금 조정이다. 현재 달러 현금의 평균 취득환율을 유지해 원가 장부도 맞춘다. 원가 근거가 없는 달러 잔고 증가에는 확인한 평균환율이 필요하다. 원래 매매·보유 수량·보유 원가·과거 성과 스냅샷과 외부 입출금은 덮어쓰지 않는다. 정산 이후 평가액에는 조정된 잔고가 사용된다.
- 계좌 단위 정산은 과거 매매별 비용을 확인했다는 뜻이 아니다. 개별 거래의 미확정 표시는 임의로 확정하지 않는다. 귀속을 확인한 실제 비용은 기존 수동 비용 입력을 사용할 수 있다.
- 반복 알림·같은 요청의 재전송은 기존 감사·중복 방지 경로를 사용한다. 이번 변경에서 새로운 부분 체결 수신기를 구현하지 않았다. 기존 알림 입력의 주문번호/중복 검증은 유지한다.
- 기존 기록에 새 요율을 소급 계산하지 않는다. 현재 운영 계좌의 2,010원/$2.029 차이도 이번 로컬 개발에서 변경하지 않았다.

## 저장 구조와 호환성

- 추가 DB 필드: `accounts.fee_schedule JSONB NOT NULL DEFAULT '{}'`. 새 공개 테이블·권한·RLS 정책은 추가하지 않는다. 로컬 PostgreSQL에서 기존 스키마에 필드를 추가하는 과정을 반복 검증한다.
- 거래의 기존 `trade_costs`에 적용 요율·시작일·상품군·절사 단위·예상/미차감 상태를 저장한다. 이후 계좌 설정 변경이나 거래 취소는 해당 거래의 저장 당시 금액을 따른다.
- 정산은 기존 `ledger_adjustments` 감사·미리보기 토큰·잠금·취소 기능을 사용한다. `COST_SETTLEMENT`와 `BALANCE_SETTLEMENT`를 구분하고, USD 정산은 기존 USD 감사 이벤트와 연결한다.
- 자동 수수료가 설정된 계좌를 저장/매매할 때 `account_fees_protocol=1`을 확인한다. 구버전 백엔드가 비용을 조용히 무시하게 두지 않는다.
- 다른 작업 폴더의 자동매수 개발은 변경하지 않았다. 향후 통합 시 공통 매매 API에서 비용을 생략하면 자동 정책이 적용되고, 명시한 실제 비용(0 포함)은 자동 정책보다 우선한다는 계약을 지켜야 한다.

## 운영 반영 전

운영 DB 접속·변경, 주문, 커밋·push·merge·배포는 이번 개발에서 수행하지 않는다. 사용자 검토 후 반영 승인 시 최신 main과 병렬 개발 변경을 확인하고, 백업·보존 대상 지문을 확보한 뒤 백엔드와 프런트엔드 버전을 맞춰 배포한다. 새 필드의 기본값은 미설정이므로 요율을 입력하기 전에는 새 자동 비용을 발생시키지 않는다. 수수료율은 확인된 계좌별로 입력한다. 기존 금융 기록과 성과는 유지한다.

롤백 시 이미 저장한 비용·감사 이력과 새 필드를 삭제하지 않는다. 구버전은 예상 비용 상태를 해석하지 못할 수 있으므로 단순 과거 버전 전환만으로 회계 검증을 생략하지 않는다. 운영 반영·복구 절차는 승인된 배포 단계에서 실제 배포 버전을 기준으로 확정한다.
