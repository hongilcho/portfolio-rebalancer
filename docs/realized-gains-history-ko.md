## 계산 및 데이터의 확실성

- 원가는 **계좌·종목별 이동평균**이다. 부분 매도에는 남은 원가와 확인된 매입 비용을 비례 배분한다.
- 비용 전 매도손익 = 매도대금 − 배분 취득원가.
- 순손익 = 비용 전 매도손익 − 배분 매입 비용 − 매도 비용. 취득원가·매입비용·매도비용을 모두 확인한 거래만 확정 순손익으로 집계한다.
- 요약의 ‘계산 가능한’ 손익과 ‘비용 확인 완료분’은 각각 확인 가능한 거래의 소계다. 미확인 거래 건수를 함께 표시한다. 전부 미확인인 소계는 0원으로 확정하지 않는다.
- 기존 수수료 없는 기록을 0원으로 소급 확정하지 않는다. 과거 기록은 비용 전 손익을 우선 확인하며, 기존 거래의 비용만 별도로 수정하는 기능은 이번 범위에 포함하지 않았다.
- 과거 매입 이력이 없을 수 있어 새 매도 시 매도 직전의 장부 원가도 저장한다. 전체 매매 이력으로 재계산할 수 있으면 이력을 우선하며, 부족할 때만 이 장부 기준을 사용하고 이전 매입 비용 미확인을 표시한다. 현재 장부 원가를 과거 매도로 잘못 적용하지 않도록 과거 날짜 삽입에는 현재 원가 스냅샷을 붙이지 않는다.
- 최초 등록·원가 정정 INIT는 매매수익이나 현금 입금으로 계산하지 않는다. 원가 정정이 포함된 보유기간을 구분한다.
- 미국 자산은 달러 가격 손익, 매도 기준환율로 원화 환산한 손익, 환율 효과를 분리한다. `원화 비용 전 손익 = 달러 가격 손익 × 매도 기준환율 + 환율 효과`. 매도 이후 보유 달러의 환차손익과 세금 신고 계산은 별개다.
- 배당은 저장된 공시 캐시와 기존 배당 계산기를 사용한 계산값이다. 추가 외부 조회를 하지 않으며 실제 입금 확인값으로 표현하지 않는다. 전량 매도 후 지급되는 배당도 배당락일의 보유 이력으로 귀속한다. 미국 배당은 달러로 표시한다.
- 기존 수동 배당금 총액은 그대로 보존하지만, 보유기간별 배분 근거가 없어 여러 기간에 복제하지 않는다. 캐시·기간 배분 근거가 없으면 확인 필요로 표시한다.

### 이번 세 종목만 일회성 처리

관리 스크립트 `scripts/repair_realized_openings_once.py`를 사용한다. 앱 시작이나 배포만으로 실행되지 않으며 일반 API에서는 실행할 수 없다. 대상은 다음 세 보유분으로 고정한다.

- 해외ETF직투계좌: VT, PDBC (US)
- 금현물계좌: M04020000 (KR)

계좌 별칭·종목코드·시장·동일 포트폴리오 소속을 확인한다. 대상이 없거나 여러 개면 임의로 선택하지 않고 중단한다. 세 보유분의 내부 식별자, 현재 수량·원화/달러 장부 원가, 거래 지문을 비공개 사전 확인 파일에 저장한다. 원래 매도가 있거나 원가가 부족한 경우도 자동 적용하지 않는다.

1. **사전 확인**: `--prepare`는 읽기 전용 트랜잭션으로 조회하고 서버 내부 비공개 파일만 새로 만든다. 인증정보·실제 금액은 콘솔에 출력하지 않는다.
2. **별도 승인 후 적용**: `--apply`는 그 파일의 정확한 세 종목만 처리한다. 장부 변경 여부를 잠금 후 다시 확인한다. 서로 다른 포트폴리오에 걸쳐도 세 종목 전체를 한 트랜잭션으로 기록하며, 하나라도 실패하면 모두 미반영이다.
3. **재실행**: 고정된 작업 요청 번호를 사용하므로 같은 작업 파일의 재시도는 이미 저장한 결과를 확인한다. 임의의 새 대상으로 반복 확정하는 일반 기능이 아니다.
4. **되돌리기**: `--rollback`은 원래 금융 기록을 수정하지 않고 보완 취소 이력을 추가한다. 보완 이후 매도손익이 남아 있으면 세 종목 전체 취소를 미반영한다. 매도부터 정상 취소하거나 별도 점검해야 하며, 평상시 매매 입력을 막는 제한은 아니다.

실행 예시(운영에서는 배포 승인·백업·대상 확인 후에만, 아래 명령은 아직 실행하지 않음):

# 기존 인증정보를 비공개로 전달받은 관리 프로세스 안에서 실행.

python scripts/repair_realized_openings_once.py --connection-env SUPABASE_URL --apply /private/realized-three.json

환경변수가 없으면 중단한다. 설정 파일을 자동 탐색하거나 운영 DB에 자동 접속하지 않는다. 사전 확인 파일에는 보유 정보가 있으므로 서버 내부 권한 0600의 비공개 경로에 두고 Git·대화·외부 파일로 내보내지 않는다.

### 보존 범위

확인한 수량·원가와 포함된 과거 거래의 지문만 기존 보호된 `bookkeeping_requests`에 별도 scope로 저장한다. 신규 테이블·열·권한·RLS 변경은 없다. 기존 수량, 평단가, 예수금, 원래 매매, 달러 원가 이벤트, 기간 성과 기준일과 기존 배당 누계는 변경하지 않는다. 이전 미확인 매입 비용을 0으로 확정하지 않는다.

1번 현황 요약과 7번 보고서는 동일한 계산 기준을 읽는다. 이후 매수·부분/전량 매도·재매수·취소 및 기준 이후 과거일 매매의 재생에도 같은 장부 원가를 사용한다. 재생용 INIT는 메모리에만 존재하며 거래 DB에 삽입하지 않는다. 실제 최초 매수일과 계산 기준일도 구분한다.

확정 전 기록이 변경되거나 기준일 전 거래가 새로 들어오면 확인 경고를 표시하고 해당 원가 손익을 확정값으로 내보내지 않는다. 기준에 포함된 과거 거래의 직접 삭제는 막고 기존 5번 탭 장부 정정 또는 별도 점검으로 안내한다.

### 로컬 검토

`http://127.0.0.1:5201/dev/realized-gains/index.html`은 합성 세 보유분에 일회성 보완이 적용된 상태를 보여준다. 등록·취소 버튼은 없으며, 보완 근거 조회와 일반 매매·취소를 시험할 수 있다. 예시 초기화는 메모리 DB의 합성 데이터를 다시 만들 뿐이다.

```powershell
python scripts/preview_realized.py --port 8133 --legacy
# 별도 터미널, 같은 작업 폴더의 frontend에서
$env:VITE_API_BASE_URL='http://127.0.0.1:8133'
npm run dev -- --host 127.0.0.1 --port 5201 --strictPort
```

기존 5200 예행과 CMA·자동매수 작업을 보존한다. 임의 가격·예수금·계좌로 중복 패턴만 재현했으며 실제 운영 자료를 이 작업에서 읽거나 수정하지 않는다. 최신 합성 검증 결과는 아래에 기록한다.

최종 검증: 백엔드 **621 통과 / 기존 5 제외**, 프런트엔드 **213 통과**, 린트·프로덕션 빌드 통과. PostgreSQL 17 **13개 시나리오 통과**, 외부 호출 0·운영 쓰기 0·임시 클러스터 종료 확인. 8개 금융 테이블 불변, 세 종목/포트폴리오별 원자적 적용, 늦은 실패 시 모든 기록 롤백, 동시 재실행 1회 반영, 되돌리기 재실행, 새 매도 후 관리 롤백 거부와 정상 매도 취소 복원, 일반 HTTP 등록/취소 경로 404를 검증했다. 기존 Starlette/httpx 사용 중단 예정 안내 1건만 남는다.

일회성 보완 뒤 새 매매가 생기면 이 기준을 읽지 못하는 이전 백엔드로 되돌려 쓰기를 재개하지 않는다. 이 경우 쓰기를 잠시 멈추고 기준을 보존하는 수정 버전으로 복구한다. 사용자의 운영 반영 승인에 따라 백업 → 코드 배포 → 세 종목 일회성 적용 → 금융 기록 불변·정상 조회 확인 순서로 진행한다.
