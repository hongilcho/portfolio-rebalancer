# Supabase 및 FastAPI 보안 보완 — 운영 적용 전 검토

## 확인한 사실

검토 기준은 main 91f513f이다. 사용자가 제공한 2026-10-09 18:58 KST Advisor CSV의
public 테이블 20개는 앱의 생성 목록과 일치한다. 제공한 권한 메타데이터에서 모든 대상은
postgres 소유, RLS 비활성, 소유자의 BYPASSRLS 활성, 세 API 역할의 전체 테이블 권한을 가진다.
Render 연결 사용자명은 postgres.프로젝트ID로 확인됐다. 사용자에 따르면 다른 연동은 없다.
사용자가 Data API를 비활성화하고 운영 자산 조회가 정상임을 확인했다.
운영 침해·유출 여부, 원격 요청 차단의 실제 결과를 에이전트가 확인한 것은 아니다.

## 변경 범위

### 앱 인증

- 기존 APP_PASSWORD 로그인으로 서명·기한 검증이 있는 12시간 Bearer 세션을 발급한다.
  ItsDangerous 2.2의 TimedSerializer와 HMAC-SHA256을 사용한다.
- 단일 소유자가 전체 포트폴리오를 운영하는 기존 모델을 유지한다. 다중 사용자별 소유권 분리를
  추가한 것이 아니다.
- APP_SESSION_SECRET은 APP_PASSWORD와 다른 무작위 비밀값이며 최소 32자다. 예측 불가능한
  32바이트 이상(예: 64자리 무작위 hex)을 사용한다. 값은 채팅·Git·프런트 환경변수에 넣지 않는다.
- 비밀번호 또는 서명 키 변경으로 기존 토큰을 무효화한다. 토큰에 비밀번호·계좌 내용은 담지 않는다.
- 인증 미들웨어가 모든 HTTP 요청을 보호한다. GET /api/health와 POST /api/auth/verify만
  인증 없이 허용한다. 공개 /docs·/openapi.json은 제거한다.
- APP_PASSWORD 또는 안전한 서명 키가 없으면 DB 초기화 전에 시작을 중단한다.
- 로그인 입력 검증 오류는 비밀번호를 응답에 반사하지 않는다. 인증/데이터 응답은 no-store다.
- 로그인 시도 제한은 프로세스당 IP별 5분 10회, 전체 120회이며 메모리를 제한한다.
  여러 프로세스·인스턴스에 공유되는 제한은 아니다. 현재 단일 Uvicorn 프로세스 기준이다.
  다중 인스턴스로 확장할 때 외부의 공통 제한 또는 공유 저장소를 설계한다.
- APP_ALLOWED_ORIGINS는 명시적 주소 목록이다. 운영 기본은
  https://portfolio-rebalancer-lemon.vercel.app 이다. 와일드카드는 허용하지 않는다.
  로컬 실행에서는 localhost/127.0.0.1의 5173~5199 포트를 추가한다.
- 토큰은 sessionStorage 및 탭 메모리에 보관하고 요청 헤더로만 보낸다. 과거 localStorage의
  portfolio_auth=true는 인증으로 인정하지 않는다. 로그인 만료/로그아웃 시 조회 캐시를 제거하며
  자동 저장된 매매/NH 초안·정확한 미확정 요청은 유지한다. 재로그인 후 같은 요청으로 결과를 확인한다.
  아직 제출하지 않았고 자동 저장이 없는 폼의 값은 재로그인 시 재입력이 필요할 수 있다.
- 로그아웃은 현재 탭의 세션을 제거한다. 개별 토큰의 서버 revocation 목록은 추가하지 않았다.
  유출 의심 시 비밀번호 또는 서명 키를 교체하고 재배포하면 모든 기존 세션이 무효화된다.
- CSV 압축 백업은 인증된 fetch와 Blob 다운로드로 바꾼다. ZIP 형식을 유지하며 URL에 토큰을 넣지 않는다.
- Authorization 헤더로 인해 최초 교차 출처 요청에 CORS 사전 요청이 추가된다. 사전 요청은
  현재 미들웨어 기본값 600초로 캐시되며 DB에 접근하지 않는다.
- 서버 인증에 DB 조회를 추가하지 않았다. 기존 시장 캐시·종가 스케줄러·장부 계산식은 유지한다.

### DB 권한 및 RLS

- migrations/security/20261009_apply.sql은 실제 이름을 확인한 앱 테이블 20개만 대상으로 한다.
  public 전체를 순회하며 모든 테이블을 바꾸지 않는다.
- PUBLIC/anon/authenticated/service_role의 테이블 권한, 해당 컬럼의 개별 권한,
  연결된 시퀀스 권한을 회수한다. postgres 소유권/기존 접근은 유지한다.
- 대상의 RLS를 켜며 허용 정책을 추가하지 않는다. 기존 정책이나 FORCE 설정을 임의 삭제·변경하지 않는다.
- 테이블 수·종류·소유자·역할을 검사한다. 미확인 노출 테이블/뷰, API 호출 가능한 SECURITY DEFINER 함수,
  별도 검토할 grant chain, 상속으로 남는 권한이 있으면 적용을 중단한다.
- 모든 변경은 한 트랜잭션에서 수행한다. 잠금 제한 5초, 실행 제한 60초와 기존 초기화 advisory lock을 사용한다.
  단순 실패는 ROLLBACK한다. 강제로 권한을 확대하거나 CASCADE로 다른 객체까지 회수하지 않는다.
- 변경 전 테이블·컬럼·시퀀스 ACL, grant option, RLS/FORCE 상태를 postgres 전용
  portfolio_security.migrations에 보관한다. 이 비공개 스키마/테이블은 보안 설정 복구용이며
  잔고·거래 데이터는 저장하지 않는다. API 역할의 schema/table 권한을 회수하고 RLS를 켠다.
- 롤백 SQL은 저장한 설정을 사용한다. 알 수 없는 기본 권한을 임의 추측하여 GRANT ALL로 복원하지 않는다.
- postgres의 전역/스키마 기본 권한을 지금 바꾸지 않는다. 기본 권한 변경은 다른 생성 경로에도
  영향을 줄 수 있으므로 읽기 전용 검사에 포함한다. 앱의 신규 객체는 생성과 같은 트랜잭션에서 보호한다.
  새로운 테이블을 추가할 때 APP_TABLES/SQL/버전/롤백 검증을 함께 갱신한다.
- 시작 보호는 PORTFOLIO_DB_SECURITY_ENABLED=1일 때만 동작한다. 기본 0이므로 코드 배포만으로
  운영 권한을 자동 변경하지 않는다. 검증·승인된 운영 SQL 적용 후 1을 설정해 반복 시작도 보호한다.
- 정상 연결은 테이블 소유자 postgres의 기존 BYPASSRLS에 의존한다. 별도의 runtime 최소 권한 역할과
  DDL 연결 분리는 향후 작업이다. RLS로 FastAPI 인증 취약점을 대신 해결하는 구조가 아니다.

## 운영 적용 순서 — 별도 승인 필요

1. Data API는 꺼짐으로 유지한다.
2. 20261009_inspect.sql을 SQL Editor에서 실행해 읽기 전용 메타데이터를 제공한다.
   함수 본문, 키, 접속 URL, 실제 자산 데이터는 조회하지 않는다.
   사전 조건에 맞지 않는 함수/뷰/역할 상속이 발견되면 변경안을 다시 검토한다.
3. DB 백업의 실제 존재·복구 방법을 확인한다. 본 개발에서 운영 백업을 읽거나 생성하지 않았다.
4. Render에 APP_SESSION_SECRET을 비공개로 설정한다. APP_PASSWORD는 기존 값을 사용한다.
   운영 URL이 기본과 다르면 APP_ALLOWED_ORIGINS를 설정한다.
   Vercel에는 서명 키를 설정하지 않는다.
5. 짧은 장부 입력 중단 시간을 잡고 승인한 DB SQL을 실행한다. 실패하면 ROLLBACK하고 원인을 확인한다.
   스냅샷 테이블 생성도 별도 운영 적용의 일부다.
6. 새 코드 main 병합/push 및 Render 수동 배포와 Vercel 배포를 함께 완료한다.
   프런트·백엔드 버전이 다르면 로그인이 거절되거나 기존 요청이 401을 받으므로 그동안 입력하지 않는다.
   PORTFOLIO_DB_SECURITY_ENABLED=1은 DB 변경 승인을 받은 뒤 설정한다.
7. 재로그인 후 운영 조회, 백업 다운로드, 정상 기능과 종가 배치 상태를 사용자가 확인한다.
   장부 쓰기는 실제 필요한 거래로 확인하며 가짜 거래를 운영 DB에 넣지 않는다.
8. 승인된 별도 검증으로 비인가 HTTP 차단과 API 역할의 실제 권한 차단을 확인한다.
   이 개발 단계의 합성 검증만으로 운영 완료를 선언하지 않는다.

## 롤백

- 일반 SQL 오류는 트랜잭션을 ROLLBACK한다.
- 커밋 후 되돌려야 할 때 20261009_rollback.sql을 사용해 보관한 ACL/RLS 상태를 복원한다.
  Data API는 꺼짐을 유지한다. 원래 위험한 권한이 돌아오므로 필요한 긴급 복구에만 사용한다.
- 재적용을 막으려면 PORTFOLIO_DB_SECURITY_ENABLED=0으로 설정하고 재배포해야 한다.
  스냅샷 복원 후 버전 행만 삭제한다. private 메타데이터 테이블은 남는다.
- 계좌·잔고·거래·성과 기록을 코드/보안 SQL 롤백으로 취소하거나 삭제하지 않는다.
- 인증 전의 코드로 돌아가면 API 보호가 사라진다. 인증을 유지하는 수정 버전을 우선 사용하고,
  이전 코드로 복귀가 꼭 필요하면 외부 접근 제한/서비스 일시 중단을 함께 결정한다.
