# 운용 편의 및 기간 성과 기능

브랜치: `codex/portfolio-workflow`. 기능별 로컬 커밋 후 사용자 확인 전에는 push하지 않습니다.

## 화면 구성

- **1. 포트폴리오 현황**: 현재 보유자산·예수금·자산 배분·계좌별 현황.
- **4. 매매 및 입출금 기록**: 매매 일괄 입력·체결 메시지 가져오기·달러 원가/환전 관리와 외부 투자자금 입출금 입력/취소/복원.
- **6. 분석 및 확인**: 일별·월별·연간 기간 성과/평가 기록, 예금 만기 안내, 배당 계산 상세 보기. 기간 성과 시작 기준 등록과 수집 상태 확인도 이 탭에서 합니다.

4번과 6번에는 상대 탭으로 이동하는 버튼이 있습니다. 아직 시작 기준이 없으면 4번에서 6번의 등록 화면으로 안내합니다. 메뉴는 좁은 화면에서 줄바꿈하여 6번도 표시합니다.

## 1. 매매 입력 임시 저장

매매기록의 매수·매도 입력 행과 날짜를 브라우저에 자동 저장합니다. 카카오톡 원문은 저장하지 않고, 추가된 행의 주문 식별 정보는 보존합니다. 저장은 포트폴리오별로 분리하며 보관 기간은 30일입니다. 다른 브라우저·기기에서는 공유되지 않습니다.

새로고침·탭 이동 후 복원되면 날짜·계좌·장부 중복 확인 체크박스를 선택해야 일괄 저장할 수 있습니다. 저장 응답이 유실되거나 전송 중 화면을 닫았을 때는 장부에 이미 반영되었을 가능성을 경고합니다. 수동 입력에는 주문번호가 없어 자동 중복 판별이 불가능하므로 최근 매매기록을 반드시 확인합니다.

성공한 행은 임시 저장에서도 제거하고, 실패한 행은 유지합니다. `임시 입력 모두 비우기`는 입력 내용만 지우며 저장된 거래·잔고에는 영향을 주지 않습니다. 브라우저 저장이 차단되면 경고를 표시하고 기존 입력 기능은 계속 사용할 수 있습니다.

검증: 저장·복원/포트폴리오 분리/손상·만료·저장 오류/부분 성공 테스트, 브라우저에서 체결 메시지 행 추가 후 새로고침하여 날짜·단가·수량·주문번호와 확인 절차 유지 확인.

## 2. 예금 만기 안내

6번 ‘분석 및 확인’의 `예금 만기 안내`를 펼치면 자산 마스터에 원금이 양수로 등록된 예금의 만기순 목록·D-day·원금·등록 조건에 따른 예상 세후 만기금액을 확인할 수 있습니다. 기존 총자산 계산과 동일하게 별도 보유 행이 없어도 포함하며 예금 하나를 여러 계좌 보유 행으로 중복 계산하지 않습니다. 30일 이내와 만기 경과 건수를 요약합니다. 미등록/잘못된 날짜는 계산하지 않고 확인 필요로 표시합니다.

기존 예금 평가와 같은 365일 일할이자·세금 내림 규칙을 사용합니다. 은행 지급액을 확정하는 기능이 아니며 만기에도 자산·예수금을 자동 수정하지 않습니다. 예금 제외 보기에서도 만기 안내는 유지합니다. 외부 조회나 새 DB 기록은 없습니다.

## 3. 배당 계산 상세 보기

6번 ‘분석 및 확인’에서 `배당 계산 상세 보기`를 펼칩니다. 계좌별로 필터링하고 배당락일·당시 수량·주당 배당·세전/세후 계산액·계산 세금을 확인합니다. 원화/달러 합계는 통화별로 구분하고, 수동 보정 등으로 계산 내역 합계와 손익 반영액이 다르면 안내합니다.

기존 대시보드 응답의 `dividend_details`를 사용하므로 추가 API 호출·DB 기록은 없습니다. 예금 제외 토글과 독립적입니다. 표시된 날짜는 실제 지급일이 아니며 현금 입금을 자동 반영하지 않습니다. 현재 조회되는 잔고 및 거래 기록을 기준으로 하며 이미 정리된 과거 보유분의 완전한 배당 장부가 아닙니다.

## 4. 리밸런싱 계획 저장·진행 확인

계산 후 계획 이름을 정하여 저장합니다. 계산 당시 조건과 매매·이체 지시를 보관하고, 저장 이후 장부에 입력한 동일 계좌·종목·매수/매도 방향의 거래를 사용자가 연결합니다. 연결된 수량·실제 금액·남은 수량·초과 수량을 비교합니다. 한 거래는 한 계획 행에만 연결할 수 있으며 연결을 해제해 다시 배정할 수 있습니다. 실제 거래를 삭제하면 진행 수량에서도 제거됩니다.

계획 보관/복원은 가능하며 저장·연결·해제·보관 모두 실제 거래·보유잔고·예수금을 변경하지 않습니다. 이체 지시는 보관만 하며 진행을 자동 판정하지 않습니다. 과거 장부를 현재 계획의 실행으로 잘못 계산하지 않도록 저장 시점의 거래 순서 기준을 사용합니다. 계좌·자산 이름은 저장 당시 이름입니다. 조회 버튼을 누르기 전에는 추가 조회를 하지 않습니다.

## 5. 월별·연간 기간 성과

6번 ‘분석 및 확인’의 `기간 성과`에서 현재 장부를 확인한 뒤 `기간 성과 시작 기준 등록`을 누릅니다. 그 시점의 평가액·구성·환율을 시작 기준으로 보존합니다. 기준은 자동으로 생기지 않으며 한번 등록한 기준을 새 값으로 덮어쓰지 않습니다. 기존 보유자산 수익률과 계산 범위를 구분합니다.

선택한 포트폴리오의 주식/ETF/금/예금 및 원화·달러 예수금 전체를 원화로 평가합니다. 가상자산·다른 포트폴리오는 제외합니다. 배당은 실제 예수금 잔고에 들어온 부분만 반영되며 계산된 배당을 다시 더하지 않습니다. 예금은 기존 총자산 계산과 동일하게 자산 마스터에 등록된 원금 양수의 예금을 한 번씩 평가합니다.

등록 이후 백엔드가 KRX 거래일 한국 시간 16:00에 정규장 종가로 자동 평가 기록을 저장합니다. 앱 조회는 기존 기록을 덮어쓰지 않습니다. 늦게 마감하는 거래일에는 마감 30분 후 수집합니다. 실패·재시작·당일 장부 정정·월말 경계·운영 설정의 상세는 [종가 기준 기간 성과](closing-performance.md)를 따릅니다. 이전 조회 기록은 종가 기록과 구분해 보존합니다.

4번 ‘매매 및 입출금 기록’에서 포트폴리오 밖에서 들어오는 투자금과 밖으로 나가는 출금은 날짜·계좌·방향·통화·금액·당시 환율(USD)을 별도 기록합니다. **성과 계산용 기록만 저장하며 예수금은 변경하지 않습니다.** 기존 잔고 수정/동기화에서 실제 현금잔고를 먼저 반영하고 중복 여부를 확인합니다. 포트폴리오 내 계좌 이동·매매·환전·배당은 외부 입출금이 아닙니다. 다른 포트폴리오와의 이동은 각각 출금/입금입니다. 계좌·보유자산을 직접 추가/삭제하여 외부 자산이 이동한 경우에도 해당 시가를 입출금으로 기록해야 합니다. 시작일 당일에는 기준 등록 이후 발생한 흐름만 기록합니다.

입출금 저장 요청 번호를 보존하므로 같은 요청 재전송을 중복 저장하지 않습니다. 기록 취소/복원이 가능하며 모두 잔고를 변경하지 않습니다. 외부 입출금 기록이 없으면 입출금 없음으로 계산하고, 기록된 입출금은 날짜·금액을 자동 반영합니다. 추가·취소·복원 및 새 평가일마다 수익률·손익을 재계산하며 매일 확인할 필요는 없습니다. 실제 외부 입출금이 발생하면 4번 탭에 기록하고 예수금도 반영해야 합니다.

일반 조회는 평가액·날짜 등 작은 메타데이터만 반환합니다. 각 날짜의 계좌/보유/시세 구성 원본은 DB에 보존하되 매번 내려받지 않습니다. 원본을 포함한 전체 보존은 DB 백업 대상이며 기존 CSV 백업의 출력 범위를 확대하지는 않습니다.

기간 손익은 `종료 평가액 - 시작 평가액 - 순입금`입니다. 수익률은 날짜별 입출금을 반영한 **금액가중 기간 수익률**(XIRR과 동일한 날짜 할인식의 기간 환산)이며 연환산·시간가중 수익률이 아닙니다. 당일 안의 발생 시각은 모델링하지 않습니다. 여러 부호 전환으로 해가 불확실한 흐름은 임의의 해를 선택하지 않고 계산 불가 안내를 표시합니다. 월별·연간 각각 직접 계산하며 월별 수익률을 단순 합산하지 않습니다.

첫 월/연은 시작 기준 등록 이후의 부분 기간입니다. 현재 월/연은 최근 평가일까지입니다. 완결된 월/연에는 해당 월말/연말 및 이전 경계일 평가액이 필요하며 누락 시 계산 대기로 표시합니다. 과거 시세만으로 누락된 잔고 평가액을 역산하지 않습니다. 기록 시점·입출금 입력·실제 장부 잔고·시장 시세 품질에 의존하므로 과거의 정확한 종가 수익률을 보장하지 않습니다.

## 기간 성과 그래프

6번 탭의 기간 성과 표 위에 막대그래프를 표시합니다. `월별 / 연간`, `수익률 (%) / 손익 (원)`을 전환할 수 있고, 월별 보기는 연도를 선택합니다. 막대를 클릭·터치하거나 키보드 Tab/Enter/Space로 선택하면 해당 기간·정확한 값·계산 대기 사유를 확인할 수 있습니다. 지표를 바꿔도 선택한 기간은 유지합니다.

표와 동일한 서버 계산 결과를 사용합니다. 경계일 평가액 부족이나 계산 불가 수익률은 0으로 대신 그리지 않습니다. 실제 0%/0원은 기준선에 별도로 표시합니다. 입출금 확인 여부에 따른 빈 점·점선 표시는 없고, 반영한 외부 입출금이 있을 때는 선택한 기간의 건수를 표시합니다. 시작 기준 이후의 첫 기간과 최근 평가일까지만 있는 진행 중 기간을 표시하며, 월별 수익률을 합산하여 연간 값을 만들지 않습니다.

6번 탭의 기간 성과는 그래프와 표를 먼저 표시합니다. 기록 상세·그래프 설명·기록 관리/수집 상태·계산 방식은 기본적으로 접어두고 필요한 경우 펼쳐 봅니다. 매일 누르던 확인 체크박스와 버튼은 제거했습니다.

SVG와 브라우저 기본 기능만 사용하고 새 차트 패키지·API 호출·DB 변경은 없습니다. 그래프 코드는 6번 탭을 열 때 불러옵니다. 좁은 화면에서는 그래프 영역만 좌우로 이동하고 최신/선택한 기간을 자동으로 보이게 합니다. 기존 표는 계속 표시합니다.

## 배포 범위

다섯 기능을 한 번에 main에 병합·push할 수 있습니다. Vercel 프런트엔드와 Render 백엔드 양쪽 배포가 필요합니다. 새 계획/성과 테이블을 추가하는 DDL만 수행하며 운영 거래·잔고를 새 계산 기준으로 수정하지 않습니다. 운영 백업 후 배포하며, 기존 코드로 롤백하더라도 새 테이블은 유지됩니다. 운영 DB에 시작 기준이나 테스트 기록을 미리 등록하지 않았습니다.

## 통합 검증

백엔드 pytest 229개 통과, 기존 격리 DB가 필요한 5개 제외. 프런트엔드 76개 테스트 및 lint/production build 통과. `scripts/verify_workflow.py`는 새 합성 PostgreSQL에서 계획 연결·입출금 재전송·확인 충돌·취소/복원·시세 누락/만료 및 실제 장부 불변을 검증합니다. 기존 운영 백업을 별도 로컬 DB에 복원한 `scripts/verify_postgres.py` 13개 검증에서 DDL 반복/동시 실행과 원본 데이터 보존을 확인했습니다.
