## 초기화 잠금 보완

기존 세션 단위 pg_try_advisory_lock/pg_advisory_unlock은 거래 풀러를 통한 세션 유지에 의존했습니다.
pg_advisory_xact_lock으로 바꿔 트랜잭션 종료 시 자동 해제하고, 다른 초기화가 끝나기를 기다립니다.
잠금 대기는 30초로 제한하며 초기화 실패를 숨기지 않고 서버 기동을 중단합니다.

## Vercel 자동 배포 보류 절차

공식 문서: https://vercel.com/kb/guide/how-do-i-use-the-ignored-build-step-field-on-vercel

Ignored Build Step 명령이 종료 코드 0이면 빌드를 건너뛰고, 1 이상이면 빌드를 진행합니다.
프로젝트 Settings → Build and Deployment의 Ignored Build Step을 일시적으로 Custom 명령 `exit 0`으로
설정하면 신규 자동 빌드를 보류할 수 있습니다. 변경 전에 현재 옵션·명령을 기록합니다.
기존 운영 배포를 중지하거나 삭제하는 기능을 사용하지 않습니다.

1. main push 전에 보류 설정을 저장하고 확인합니다.
2. push 후 새 커밋의 Vercel 빌드가 건너뛰어졌는지 확인합니다. 기존 운영 도메인은 기존 배포를 유지해야 합니다.
3. Render에서 같은 새 커밋을 수동 배포하고 DB 초기화·health·잔고를 확인합니다.
4. Ignored Build Step을 기록해 둔 원래 설정으로 복구합니다.
5. Deployments의 Create Deployment로 main의 새 커밋을 명시해 프론트엔드를 배포합니다.
   재배포를 사용할 경우 기존 운영 커밋이 아니라 새 커밋인지 확인합니다.
6. 운영 도메인과 두 서비스의 커밋·수익률을 확인합니다.

Codex 브라우저에서 해당 설정 주소를 열었으나 Vercel 로그인 페이지로 이동했습니다.
실제 대시보드의 현재 옵션은 확인하지 못했고 설정을 변경하지 않았습니다.

이후 사용자가 Ignored Build Step을 Custom / `exit 0`으로 저장했다고 확인했습니다.
