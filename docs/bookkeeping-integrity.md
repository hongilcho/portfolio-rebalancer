# 장부 입력·정정·취소의 무결성 보완

## 운영 원칙

실제 잔고·수량·원가의 변경은 5번 탭에서 처리한다. NH 알림 입력이 기본이며 수동 매매,
외부 입출금, 달러 관리, 장부 정정, 예금 장부는 예외 상황을 처리한다.
6번 설정 탭은 계좌·종목의 기본 정보와 배분 설정을 담당한다.
기존 운영 잔고나 과거 거래를 추측하여 자동 보정하지 않는다.

## 반영된 보호

- 잔고·보유·거래·정정 이력이 있는 계좌와 종목의 영구 삭제를 서버에서 차단한다.
- 보유 이력이 있는 종목의 시장·종목코드·자산 종류 변경을 차단한다.
- 설정 탭의 예금 원금·계약 조건은 읽기 전용이다. 5번 `직접 입력 → 예금 장부`에서
  등록·정정 사유, 변경 전후 계약, 요청 번호를 보존하고 최신 기록부터 취소한다.
  이 기능은 현재 예금 정보를 확인하는 기능이며 실제 가입·해지의 현금 결제를 추정하지 않는다.
  예수금과 과거 성과 기준/종가를 자동 변경하지 않는다.
- 서버 시작 시 기존 예금 계좌·보유·매매 이력을 자동 삭제하던 정리 작업을 중단한다.
- 수동 매매 묶음은 전부 성공하거나 전부 미반영이다. 계좌·종목 소속, 허용 계좌,
  결제 통화, 날짜와 금액을 서버에서 검증한다.
- 과거 거래는 기존 이력과 현재 원가가 일치하고 결제 정보가 충분할 때 거래일/거래 순서로
  재계산한다. 불충분한 기존 보유분은 지우거나 추정하지 않고 장부 정정으로 안내한다.
  달러 원가 추적 중인 과거 거래는 기존처럼 이후 기록부터 취소하는 순서를 유지한다.
- 수동 매매·환전·달러 입출금은 요청 번호와 정확한 입력 내용을 브라우저와 DB에 보존한다.
  통신 실패 후에는 같은 요청으로 결과를 조회하며 다시 반영하지 않는다. 이미 취소된
  요청을 재시도해도 다시 생성하지 않는다. 더블 클릭도 한 요청만 보낸다.
- USD 외부 입출금은 달러 잔고·원가와 성과 입출금을 한 트랜잭션에서 저장·취소한다.
  배당·이자는 외부 투자금으로 분류하지 않는다. 기존 성과 입출금은 선택하여 연결할 수 있다.
  같은 날짜·금액의 별도 실제 입금은 명시적 중복 확인 후 기록한다.
- 기존 음수 잔고도 조회/확인값으로 받을 수 있다. 실제 입금으로 정상화하거나 장부 정정으로
  복구할 수 있다. 새 거래가 예수금을 부족하게 만드는 것은 계속 차단한다.
- 성과 기준이 없는 새 포트폴리오도 실제 초기 입금을 먼저 반영할 수 있다.
  양수 평가액이 생긴 후 성과 시작 기준을 등록한다.
- 저장 후 현황·달러 원가·기록·성과 조회를 각각 시도한다. 저장 성공과 화면 조회 실패를
  구분한다. 확인 중인 요청은 입력을 잠그되 다른 확인 중인 요청으로 이동할 수 있다.

## 스키마와 배포

`data/workflow_schema.py`의 `bookkeeping_requests` 테이블이 추가된다. 기존 장부 데이터를
수정하거나 요청 번호를 소급 생성하지 않는다. 예금 원금의 기존 REAL 타입만 DOUBLE PRECISION으로
승격하여 향후 원 단위 입력의 반올림 손실을 줄인다. 이미 저장된 값은 보존하며 과거 손실을 추정 복구하지 않는다.
기존 RLS/역할/권한 설정은 변경하지 않았다.

백엔드와 프런트엔드가 모두 필요하다. 새 프런트엔드는 `/api/trades/capabilities`를 확인하고
이전 백엔드에는 새 수동 거래를 보내지 않는다. 배포 전 백업 상태를 확인하고 Render의
새 백엔드를 배포한 후 새 프런트엔드를 사용한다. 배포 간격에는 수동 입력이 대기할 수 있다.

롤백은 이전 프런트엔드와 백엔드 배포로 함께 복귀한다. 요청/정정 이력 테이블은 삭제하지 않는다.
이미 반영된 실제 거래를 코드 롤백으로 되돌리지 않는다. 거래 취소는 해당 장부 기능으로 처리한다.
구 버전에서는 새 보호 기능이 제공되지 않으므로 복구가 필요할 때는 쓰기 작업을 중단한다.

## 검증

- `python -m pytest tests -q -p no:cacheprovider`: 외부 HTTP·실제 DB를 차단한 합성 SQLite/모의 검증.
- `npm test`, `npm run lint`, `npm run build`: 화면/실제 이벤트 핸들러, 요청 복원, 갱신 실패, 이중 제출 검증.
- `python -B scripts/verify_bookkeeping_integrity.py`: 지정된 `127.0.0.1:55438`, `ledger_qa` 전용
  PostgreSQL에 새 QA DB만 생성한다. 비공개 설정을 읽지 않고 외부 HTTP를 차단한다.
  동시 매매·환전 재시도, 전체 롤백, 과거 원가, 음수 잔고 복구, 달러 성과 기록과 취소,
  예금 등록/취소와 스키마 반복 초기화를 검증한 뒤 자신이 만든 DB만 삭제한다.

이는 코드와 합성 환경의 검증이다. 운영 데이터의 실제 잔고·거래 누락 여부 및 운영 배포 상태는
별도 확인 사항이며 이 개발에서 운영 DB/API에 접근하지 않는다.
