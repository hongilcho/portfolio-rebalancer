# 실제 데이터 복사본으로 투자 회차 연습

## 현재 환경

- 화면: http://127.0.0.1:5198/
- 로컬 백엔드: http://127.0.0.1:8568/
- 로그인 비밀번호: `local-rehearsal` (연습용이며 운영 비밀번호와 무관)
- 원본 복사 시각: 2026-10-10 18:37 KST
- 최초 복원에서 21개 테이블의 행 수와 내용 해시가 같은 원본 스냅샷과 일치함을 검증했다. 로컬 앱 최초 초기화 후에도 기존 21개 테이블 데이터가 유지됨을 확인했다.
- 기존 자산·계좌·보유·매매·예수금·환전·입출금·성과·리밸런싱 계획은 복사본에 보존된다. 새 투자 실행 스키마는 복사본에만 추가된다.

## 직접 연습할 순서

1. 복사본 앱에 로그인하고 연습할 포트폴리오를 선택한다.
2. 4번 **리밸런싱 전략**에서 실제로 시험할 투자 규모와 전략을 입력하여 계산한다. 아직 들어오지 않은 신규 투자금은 실제 입금 기록이 필요한 자금으로 구분한다.
3. 계획을 저장하고 **이 계획으로 투자 실행 준비**를 선택한다.
4. 8번에서 대표 계좌와 자금 사용 범위를 확인하여 투자 회차를 시작한다.
5. 필요한 입금·이체·환전을 연습 기록으로 입력한다. 기존 돈을 다시 입금한 것처럼 입력하지 않는다.
6. 실제 증권사 거래는 하지 않고 국내·해외 매수를 가상으로 실행했다고 가정하고 **새 체결 내역 입력**에 알림 예시 또는 실제 입력 형식으로 기록한다.
이미 장부에 있는 과거 체결 알림을 다시 사용하면 중복 방지에 걸릴 수 있다. 새 거래를 연습할 때는 가상의 새 주문번호를 사용하거나 수동 입력한다.

7. 5번에 먼저 매수를 기록한 뒤 8번 **기록한 거래 가져오기**로 연결하는 경로도 시험한다.
8. 5번 기록조회와 1번 현황을 확인하고, 마지막에 8번 투자 회차를 종료한다.

외부 서비스에는 연결하지 않으므로 증권사 거래나 실제 이체가 실행되지 않는다. 입력·취소·정정은 이 PC의 복사본에만 반영된다. 한 차례 연습 후에도 복사 직후의 원본 아카이브는 유지하므로 처음 상태로 다시 시작할 수 있다.

## 실제 운영과 다른 부분

- 시세·환율·가상자산·배당은 원본 DB에 저장된 캐시 값을 사용한다. 시세 새로고침은 외부 정보를 수집하지 않는다. 따라서 현재 실시간 평가액과 차이가 있을 수 있다.
- 자동 종가 수집과 증권사 동기화는 실행하지 않는다.
- 앱 코드는 개발 브랜치 버전을 사용한다. 운영 DB를 업그레이드하지 않고 복사본만 초기화했다.
- 복사 후 운영에서 발생한 새 거래·시세 갱신은 이 복사본에 자동 전달되지 않는다. 복사본의 연습 기록도 운영에 전달되지 않는다.

## 격리와 보관

운영 연결은 복사 도구의 READ ONLY 트랜잭션과 pg_dump에서만 사용했다. 동일한 DB 스냅샷에서 데이터 해시와 아카이브를 생성했다. `auth`, `storage`, `vault`와 같은 앱 외부 스키마 및 운영 인증정보는 복원하지 않았다.

로컬 실행은 설정 파일 로딩을 끄고 명시적인 loopback DB 연결만 허용한다. DB 연결 검사와 외부 소켓/HTTP 차단, 꺼진 종가 스케줄러를 적용했다. 화면 상단에는 운영 DB 복사본을 사용하는 로컬 연습이라는 표시가 고정된다.

개인 데이터 아카이브·메타데이터·로그는 Git에서 제외된 `backups/local_rehearsal/`에만 보관한다. 일반 프런트엔드 정적 파일이나 예시 페이지에 개인 데이터를 넣지 않았다. 이 폴더를 공개 저장소에 올리지 않는다.

## 로컬 서버를 다시 켜려면

프로젝트 폴더에서 별도 터미널 두 개를 사용한다.

```powershell
python scripts/local_rehearsal.py --port 8568
```

```powershell
node scripts/local_rehearsal_ui.mjs
```

복사본 재실행은 운영 DB에 접속하지 않는다. `clone_local_rehearsal.py`는 새 원본을 다시 읽는 작업이므로 단순 재시작에 사용하지 않는다.
