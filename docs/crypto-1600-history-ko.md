# 가상자산 오후 4시 평가 복원과 공통 그래프

기준 커밋: `e02a8f4`. 개발 브랜치: `codex/crypto-1600-history`.
이 문서는 로컬 개발·검증 결과다. 운영 DB·서버·설정은 변경하지 않았고 커밋·push·main 병합·배포도 하지 않았다.

## 복원 근거와 시간 기준

사용자가 2026-10-27에 **2026-10-05 이후 BTC·ETH의 수량과 평균 매입가는 바뀌지 않았다**고 확인했다. 확인 범위는 10월 5~27일이며 미래 날짜로 자동 연장하지 않는다. 현재 장부와 다른 수량·원가로 과거를 채우지 않는다. 기준 지문이 다르면 적용을 거부한다.

- 한국시간 매일 16:00 평가. 업비트 KRW-BTC·KRW-ETH의 15:59:00 이상 16:00:00 미만 1분봉 종가를 사용한다. 가상자산은 주말·국내 휴장일에도 기록한다.
- UTC/KST 캔들 시작시각, 종목, 분봉 단위, 마지막 거래 시각, 양수·유한 가격을 함께 확인한다. 16:00~16:01 가격이나 현재 시세를 대용하지 않는다. 분봉이 없거나 공급자가 실패하면 해당 날짜를 비워 두고 재시도한다.
- 평가 시각과 저장 시각을 구분한다. 복원 지표는 RECONSTRUCTED이며 보유 불변 확인 기간, 지문, 원본 분봉 근거를 private payload에 남긴다. 그래프 API에는 원본 보유정보나 확인 영수증을 전송하지 않는다.
- 같은 날짜의 기존 가상자산 기록은 덮어쓰지 않는다. 기존 수집 구간 관측값이 있으면 배포 전 해당 날짜의 시간 기준을 별도로 검토해야 한다. 이번 운영 사전 자료에는 기존 가상자산 일별 기록이 없었다.

공식 명세: https://docs.upbit.com/kr/reference/list-candles-minutes
과거 분봉 샘플과 실제 10월 5~27일 BTC·ETH 분봉을 공개 API로 조회해 유효성을 확인했다. 계좌 API·NH 토큰·거래소 비밀키는 사용하지 않았다.

## 저장·조회와 향후 보유 변경

일별 기록은 기존 private `portfolio_analytics.crypto_snapshots`를 재사용한다. 새 테이블·권한·RLS 변경은 없다. 날짜 PK와 `ON CONFLICT DO NOTHING`으로 중복 저장과 덮어쓰기를 방지한다.

기존 `bookkeeping_requests`의 별도 `crypto-history-basis` 범위에 보유 불변 확인 및 이후 가상자산 보유 변경 기준을 추가로 기록한다. 가상자산 수정 UI에서 기존 저장을 실행할 때 그 변경과 동일 트랜잭션으로 기준을 남긴다. 기록 실패 시 수정도 롤백된다. 메모만 바뀌고 수량·원가가 같으면 새 원가 기준을 만들지 않는다. 기존 매매·입출금 기록을 새로 생성하지 않는다.

일별 수집은 기존 백엔드 스케줄러를 재사용한다. 해당 평가시각 이전에 확인된 보유 기준과 과거 분봉을 함께 사용하므로 늦은 실행·재시작 후에도 보충할 수 있다. 확인 기간 이후부터 첫 관측 시각 사이에 근거가 없는 날짜는 건너뛴다. 시점 근거가 없는 현재 보유값을 과거에 적용하지 않는다. 한 번에 하루만 처리하고 분당 최대 한 차례 확인한다. 특정 날짜 조회 실패는 10분간 유예해 다른 날짜 수집을 막지 않는다. 금융 종가 수집의 날짜·계산·저장 의미는 바꾸지 않는다.

## 사용자 화면

- 상단 선택 → **가상화폐 포트폴리오(업비트)**: 현황 카드 바로 아래에 ‘가상자산 손익 추이’를 추가한다. 손익·수익률·평가액, 일별·월말·연말, 날짜 선택, 표를 기존 공통 그래프로 제공한다. 10월 5일 손익을 0으로 초기화하지 않는다. 현재 시세 값은 별도의 빈 점과 점선으로 구분한다.
- **전체 자산 종합 요약**: 같은 가상자산 일별 기록을 금융 포트폴리오와 합산한다. 원가와 손익을 더해 수익률을 구하며 수익률을 평균내지 않는다. 가상자산 포함·제외 선택은 카드와 그래프에 같이 반영된다.
- 가상자산 단독은 달력일, 전체 합산은 금융 평가일을 사용한다. 일반투자의 10월 5·6일 기록은 원래 없으므로 전체 합산은 10월 7일부터 14개 기록이다. 이를 화면에 ‘16일 중 14일 표시 · 일반투자 기록이 없는 날짜는 합산하지 않습니다’로 안내한다. 빈 기록을 0으로 채우지 않는다.

## 복원 도구와 운영 적용 경계

`scripts/restore_crypto_history.py prepare`는 보유 수량·원가 불변 확인, 시작·종료일, 비공개 보유 파일을 명시적으로 받아 후보 manifest를 만든다. DB에는 접속하지 않고 비밀 설정 파일도 자동으로 읽지 않는다. 출력은 Git에서 제외된 `backups/`에만 저장하며 기존 파일을 덮어쓰지 않는다. 공개 분봉 대신 검증된 로컬 분봉 파일을 입력해 재현할 수도 있다.

`apply`는 별도 동작이다. 명시한 환경변수의 DSN만 사용하며 기본적으로 루프백 DB만 허용한다. 운영 적용은 사용자 승인 후 별도 `--allow-remote`가 필요하다. manifest 전체 재계산 일치, 현재 보유 지문과 기존 변경 이력을 확인하고, 확인 기준과 완성된 일별 기록만 원자적으로 추가한다. 일부 가격이 누락된 manifest는 적용하지 않는다. 그래프 GET은 이 쓰기 경로를 호출하지 않는다.

운영 승인 후에는 새 DB 백업과 원본 지문을 확보하고, 검토 당시 보유 기준이 여전히 일치하는지 확인한 뒤 배포·복원한다. 복원 확인은 10월 27일까지이므로 배포 시 추가 날짜가 생겼다면 그 구간의 수량·원가 변동을 확인한 뒤 연장한다. 원본 금융·가상자산 보유정보, 기존 매매, 예수금, 기간 성과와 모든 기존 영수증은 보존한다. 신규 분석 영수증 및 일별 기록만 허용된 추가분으로 대조한다. 코드 롤백 시에도 신규 분석 기록을 임의로 삭제하지 않는다.

## 운영 반영 승인 · 2026-10-27

사용자가 로컬 검토 후 운영 DB 선행 백업, main 병합·origin push·AWS 배포, 10월 5~27일 가상자산 평가 복원 적용을 승인했다. 검토 기준과 운영의 현재 보유 지문을 비교하고, 기존 금융·가상자산 보유정보·예수금·매매·기간 성과 원본을 보존한다. 승인된 추가분은 가상자산 일별 평가 23건과 보유 기준 분석 영수증뿐이다. 기존 RLS·권한·환경변수·금융 종가 설정은 변경하지 않는다. 분석 영수증 추가에 따른 해당 시퀀스 증가만 별도로 대조한다. 기존 코드 릴리스와 새 DB 백업을 보존하며, 배포 실패 시 코드만 롤백하고 복원된 분석 기록을 임의로 삭제하지 않는다. 배포 후 운영 가상화폐 페이지와 포함/제외 통합 그래프의 실제 표시를 확인한다.

사전 대조에서 운영 연결의 `extra_float_digits=0` 때문에 REAL 수량·원가가 짧은 문자열로 반환되어 백업의 복원 지문과 달라지는 것을 확인했다. 운영 테이블 자체는 기존 백업 이후 동일했다. 가상자산에 한해 double precision으로 읽은 값을 원래 REAL 표현으로 정규화해 단독 현황·전체 현황·복원 기준의 정밀도를 일치시켰다. 저장된 값이나 DB 설정은 변경하지 않는다. 같은 서버 설정을 격리 PostgreSQL에서 재현해 세 읽기 경로의 지문 일치와 기존 기간 성과 보존을 검증했다.
