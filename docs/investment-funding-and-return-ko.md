# 투자 자금 여유분과 CMA 현금 회수

## 이번 변경

- 새 투자 회차 준비: 가격 여유율 1%, 환율 여유율 1%를 기본값으로 제공한다. 펼친 설정에서 0~20%로 조정한다. 이전 회차와 미확정 시작 요청은 값이 없으면 0%로 유지한다.
- 매수 수량은 변경하지 않고, 해당 계좌의 기존 원화·달러 예수금을 차감하여 자금 준비액만 계산한다.
- 환전 직접 입력: 현재 장부 원화·달러 예수금과 입력한 실제 원화/달러 금액을 반영한 예상 잔액을 표시한다.
- 8번의 반복 안내를 실제 목표·기록·남은 수량을 보여주는 투자 요약으로 바꾸고, 사용 설명은 펼침 안으로 옮긴다.
- 종료한 매수 투자에서 별도의 CMA 원화 회수 계획을 만들 수 있다. 계획 저장과 시작은 장부를 바꾸지 않는다. 실제 이체 입력은 기존 공통 장부에 반영되며 5번에서도 조회한다.

## 준비 금액 계산

국내: 남은 수량 × 참고 단가 × (1 + 가격 여유율), 원 단위 올림.
해외: 남은 수량 × 달러 참고 단가 × (1 + 가격 여유율)에서 기존 달러를 차감한 부족액을 센트 단위 올림. 그 달러 × 예상 환율 × (1 + 환율 여유율)을 원 단위 올림.
이 계좌의 국내 매수·환전 준비 원화를 합산한 뒤 기존 원화를 차감하여 필요한 이체를 계산한다. 가격/환율 여유분은 비용이나 수익으로 장부에 기록하지 않는다.

국내 80만원 매수, 기존 원화 20만원, 가격 여유 1% → 60만 8천원 이체.
달러 500달러 매수, 기존 달러 100달러, 가격 여유 1%, 예상 환율 1,400원, 환율 여유 1% → 405달러 환전, 원화 572,670원 준비.
부족한 준비 자금은 추가 입금 또는 출금 가능한 다른 계좌의 한도를 확인하도록 안내한다. 절세계좌의 현금은 해당 계좌 안에서만 사용한다.

## 회수 계획 흐름

1. 매수 투자 회차 종료 후 **남은 현금 CMA 회수 계획 만들기**를 선택한다.
2. 해당 투자에 사용한 계좌의 현재 장부 잔액을 확인한다. 기존 현금도 포함된다. 실제 증권사 잔고와 다른 경우 먼저 장부를 확인한다.
3. 같은 포트폴리오의 CMA 계좌를 고른다. 계좌 종류 또는 별칭의 CMA 표시로 구분하며 절세계좌는 CMA로 선택할 수 없다.
4. 출금 가능한 계좌 중 회수할 계좌를 선택하고, 각 계좌에 남길 원화를 지정한다. ISA·IRP·연금저축·퇴직연금은 회수하지 않는다. 달러도 그대로 둔다.
5. 미리보기에서 계좌별 회수액/남길 금액을 확인하여 이름을 붙인 별도 계획으로 저장한다. 잔고가 변경되면 저장을 거부하고 다시 확인하도록 한다.
6. 그 회수 계획으로 8번 진행을 시작한다. 진행 중인 다른 투자 회차가 있으면 먼저 종료한다.
7. 증권사에서 실제 이체한 후 알림 붙여넣기 또는 직접 입력으로 이체를 기록한다. 양쪽 계좌의 원화만 변경하며 공통 장부에 한 번 반영한다.
8. 회수 회차를 종료한다. 원래 매수 투자와 회수 계획·회차 이력은 모두 보존된다.

## 저장 구조와 호환성

기존 rebalance_plans.payload에 CASH_RETURN 유형, 원본 종료 회차, CMA 입금 계좌, 원화 회수 행과 요청 내용을 저장한다. 기존 portfolio_execution의 TRANSFER 작업으로 실행하므로 새 테이블·컬럼·RLS 정책 변경은 없다. 일반 매수 계획의 기존 API는 유지한다.
회수 계획 생성에는 종료/포트폴리오/절세계좌/잔고/원 단위 검사, 잔고 미리보기 토큰 및 요청 ID 중복 방지를 적용한다. 계획만 만들면 잔고·보유·성과가 바뀌지 않는다. 실제 이체는 기존 장부의 트랜잭션·중복 방지를 사용한다.
진행 중인 기존 회차에 여유율을 소급 적용하지 않는다. 기존 회차에서 목표를 변경해도 기존 여유율을 유지한다. 회수액을 변경하려면 회수 회차를 종료한 뒤 원본 매수 투자에서 새 회수 계획을 만든다.
프런트엔드는 여유율을 지원하는 백엔드인지 확인한 뒤 준비 계산을 요청한다. 운영 반영 시에는 백엔드/프런트엔드 둘 다 업데이트해야 한다. 이번 작업은 로컬 개발만 수행했으며 원격 push·배포·운영 DB 변경은 수행하지 않았다.

## 검증

- Python 계산/요청 모델 테스트 28개: 기존 현금 차감, 국내/달러/환율 여유분, 기존 수량 유지, 기존 회차 호환, 한도 및 절세계좌 제외.
- 프런트엔드 테스트 182개, lint, 빌드 통과.
- 새 합성 PostgreSQL 통합검증: 회차 종료 조건, 다른 포트폴리오/절세계좌 회수 거부, 잔고 변경 시 미리보기 무효화, 계획·시작·이체 중복 방지, 공통 장부 반영 및 달러/보유/성과 보존.
- 기존 투자 실행 SQL 회귀검증: 시작·부분 체결·목표 변경·환전·취소·확인 실패 복구·권한 및 RLS·종료 보고서.
- Chrome 브라우저: 전체 투자 진행 후 회수액 조정 → 별도 계획 저장 → 회수 진행 → 실제 장부 이체 → 회수 종료, 기존 5번 입력/8번 연결 경로 유지. 모바일 390px 회수 화면에서 가로 넘침 없음.
- 실제 데이터 로컬 복사본: 서버 업데이트 전후 기존 장부 및 투자 회차 25개 테이블 해시 일치, 운영 연결과 외부 HTTP/스케줄러 차단 유지.
