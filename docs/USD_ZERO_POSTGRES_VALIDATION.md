# 첫 환전 기능의 로컬 PostgreSQL 동시 잠금 검증

검증일: 2026-10-15, 브랜치: `codex/usd-zero-opening`.

## 최종 결과

PostgreSQL 17.6에서 12개 검증 항목이 모두 통과했습니다. 계좌 행을 명시적으로
잠근 뒤 동시에 환전 요청을 보내 `pg_stat_activity`의 Lock 대기와
`pg_blocking_pids()`가 가리키는 실제 차단 세션을 8차례 확인했습니다.
잠금을 해제하기 전에는 초기 원가 장부나 환전 이벤트가 다른 세션에 보이지 않았습니다.

| 검증 항목 | 확인한 결과 |
|---|---|
| 서로 다른 첫 환전 2건 | 원가 장부는 1개, 이벤트는 2개. 잔액·원가가 합산됨 |
| 직접 입력의 동일 요청 동시 저장 | 응답은 2개, 현금 반영·이벤트·요청 영수증은 각각 1회 |
| NH 알림의 동일 요청 동시 저장 | 응답은 2개, 현금 반영·이벤트·배치는 각각 1회 |
| 원화가 한 건에만 충분한 동시 환전 | 1건 성공·1건 잔액 부족 거부, 실패 요청 흔적과 음수 잔액 없음 |
| 서로 다른 NH 미리보기의 동시 저장 | 선행 저장 후 나머지는 잔고 변경으로 거부됨 |
| 직접 입력과 NH 알림의 동시 저장 | 3회 교차 검증. 하나의 원장 사용, 선후 순서에 맞는 합산 또는 오래된 알림 거부 |
| 직접 입력 환전의 동시 취소 | 2개 취소 응답에도 잔액은 한 번만 복원, 원가 장부는 추적 전 상태로 복원 |
| NH 알림 환전의 동시 취소 | 묶음 취소 2회에도 한 번만 복원, 취소된 요청 재시도로 환전이 재생성되지 않음 |
| 기존 시작 기준·환전 기록 | 초기 달러 0·20 계좌 모두 시작 시각과 기존 이벤트 유지. 다시 잔액 0이 된 기존 원장도 유지 |
| 직접 입력 이벤트 저장 실패 | 실제 DB 트리거로 실패시켜 현금·초기 원장·이벤트·요청 영수증 전체 롤백 확인 |
| NH 알림 이벤트 저장 실패 | 실제 DB 트리거로 실패시켜 현금·초기 원장·이벤트·배치·항목 전체 롤백 확인 |
| 기존 미국 종목 보유분 | 수량·매입원가·배당 보정·기존 거래 유지. 추적 이전 거래 삭제 차단과 환전 취소 후 복원 확인 |

별도로 등록한 가상 계좌의 기존 시작 기준·환전 내역도 전체 검증 전후가 동일했습니다.
12개는 서로 다른 검증 항목 수이며, 8개는 실제 잠금 대기 관측 횟수입니다.
기존 pytest·프런트엔드 테스트 수와 합산하지 않습니다.

## 격리 범위와 정리

- 다른 두 개발 폴더를 재사용하지 않고, 환전 전용 worktree 안에 새 PostgreSQL
  클러스터를 만들었습니다. 기존 로컬 DB와 기존 계좌 자료를 복사하지 않았습니다.
- 서버는 `127.0.0.1:55441`에서만 수신했습니다. DB를 만들기 전 `data_directory`가
  해당 전용 클러스터인지 확인했고, 매 실행마다 새 이름의 테스트 DB를 생성했습니다.
- `.env` 등 운영 설정 로드를 비활성화하고, 연결 가드를 이 주소·포트·가상 사용자와
  해당 테스트 DB에만 허용했습니다. 외부 소켓·HTTP·NH 호출은 차단했습니다.
- 애플리케이션 코드는 추가로 수정하지 않았습니다. 검증 전후 기존 수정 파일 9개의
  SHA256이 같았습니다. 다른 두 개발 폴더에 대한 쓰기·이동·되돌림도 하지 않았습니다.
- 최종 검증이 끝난 후 이 전용 PostgreSQL 서버를 종료했고, 테스트 포트가 닫혔음을 확인했습니다.
  가상 테스트 자료는 Git에서 제외되는 `backups/` 아래에 보존했습니다.
- 운영 DB 접근, 실제 계좌 기록 변경, 커밋·push·병합·배포는 없습니다.
- 검증 범위는 로컬 PostgreSQL의 실제 트랜잭션·잠금입니다. 운영 네트워크·풀러·서버
  환경에서의 동작까지 검증한 결과는 아닙니다.
