# 카카오톡 매수 체결 메시지 가져오기

개발 브랜치: `codex/namuh-message-import` (2026-10-05)

## 사용 순서

1. 카카오톡에서 NH투자증권 매수 전량 체결 메시지를 길게 눌러 복사합니다.
2. 앱에서 해당 포트폴리오를 선택하고 **4. 매매기록**으로 이동합니다.
3. **매매 체결 기록 일괄 입력**의 체결일자를 실제 거래일로 먼저 설정합니다.
4. **카카오톡 체결 메시지 가져오기 열기**를 누르고 메시지를 붙여넣은 뒤 **내용 확인**을 누릅니다.
5. 계좌·종목·수량·체결단가·날짜를 확인합니다. 마스킹된 계좌번호가 여러 계좌와 일치하면 계좌를 직접 선택합니다.
6. 확인 체크박스를 선택하고 **매수 입력란에 N건 추가**를 누릅니다. 아직 장부에 저장되지 않습니다.
7. 다른 종목의 메시지도 같은 순서로 반복해서 추가합니다. 완전한 메시지 여러 개를 한 번에 붙여넣어도 됩니다.
8. 기존 매수 입력 행에서 전체 내용을 최종 확인·수정한 뒤 **위 내역 전체 일괄 저장**을 누릅니다.

기존에 직접 입력한 매수·매도 행을 유지합니다. 가져온 행은 선택한 체결일에 고정되므로 다른 날짜의 거래는 별도로 처리합니다. 날짜를 바꾸려면 가져온 행을 모두 삭제해야 합니다. 저장 전 입력 내용은 새로고침하면 사라집니다.

## 지원 범위

- NH투자증권 **국내 주식·ETF 매수 전량 체결** 알림을 지원합니다. ISA·IRP·연금저축도 메시지와 앱에 등록된 계좌·종목이 일치하면 이용할 수 있습니다. 계좌 API 지원 여부와 무관합니다.
- 종목코드의 숫자·영문 조합 6자리(예: `0085P0`)를 지원합니다. 계좌번호는 숫자·별표로 된 11자리 형식을 확인합니다.
- 체결 메시지의 수량과 원화 체결단가를 사용합니다. 현재 시세로 대체하지 않습니다.
- 메시지에 날짜가 없으면 화면의 체결일을 사용자가 확인해야 합니다. 날짜가 있으면 화면 날짜와 일치해야 합니다.
- 등록되지 않은 종목, 계좌에 허용되지 않은 종목은 저장할 수 없습니다. 먼저 자산 관리에서 등록·연결합니다.
- 부분 체결, 매도, 해외시장·달러 거래 및 다른 증권사 메시지는 현재 직접 입력해야 합니다. 실제 메시지 예시를 확보한 뒤 지원 범위를 확장할 수 있습니다.
- 카카오톡을 감시하거나 증권사에 주문을 보내지 않습니다. 원문 해석은 브라우저에서 수행합니다.

## 중복·저장 실패 처리

- 가져온 주문은 **계좌 + 체결일 + 출처 + 주문번호**로 식별합니다. 입력 대기 행 및 저장된 거래와 같은 주문이면 추가를 차단합니다.
- 서버에서도 계좌 잠금과 고유 인덱스로 중복 저장을 차단합니다. 새로고침·응답 유실·동시 요청 후 재시도해도 동일 주문으로 예수금을 두 번 차감하지 않습니다.
- 기존 수동 거래에는 주문번호가 없으므로 같은 계좌·종목·수량·단가가 있으면 별도 매수인지 확인하는 경고를 표시합니다. 이 경우 완전한 중복 판별은 불가능합니다.
- 일괄 저장은 기존 방식대로 **거래별 성공/실패**를 반환합니다. 성공한 행은 제거하고 실패한 행은 입력란에 남깁니다. 전체 묶음이 하나의 트랜잭션인 것은 아닙니다.
- 잘못된 저장을 명시적으로 삭제하면 기존 거래 취소 로직으로 잔고를 되돌리고 해당 주문의 출처도 제거합니다. 이후 올바른 값으로 다시 가져올 수 있습니다.
- 카카오톡 원문과 원문에 포함된 이름·마스킹 계좌번호는 DB에 저장하지 않습니다. 거래에는 `import_source='NAMUH_KAKAO'`, `broker_order_no`만 추가합니다.

## 개발·배포

- 순수 파서·매칭: `frontend/src/utils/namuhMessage.js`
- 가져오기·확인 UI: `frontend/src/components/Tab4History/NamuhMessageImport.jsx`
- 기존 일괄 저장 연동: `HistoryTab.jsx`, `TradeBatchForm.jsx`
- 거래 메타데이터·중복 차단: `backend/routers/trades.py`, `data/repositories/trades.py`
- `data/schema.py`의 `init_db()`가 `trade_history`에 nullable TEXT 컬럼 2개(`import_source`, `broker_order_no`)와 부분 고유 인덱스를 추가합니다. 기존 행의 값은 변경하지 않습니다.

배포 전 백업하고 **새 백엔드가 Live 상태가 된 다음 새 프런트엔드를 사용**해야 합니다. 구버전 백엔드는 가져오기 메타데이터를 보존하지 않으므로 새 UI를 먼저 운영에 노출하면 저장 후 중복 방지가 작동하지 않을 수 있습니다. Render 수동 배포와 Vercel 자동 배포 순서에 주의합니다.
