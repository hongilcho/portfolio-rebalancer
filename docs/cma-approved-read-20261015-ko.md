# CMA 기존 연결 읽기 전용 확인 결과 — 2026-10-15

사용자는 지정 AWS 서버의 임시 SSH 인증자료와 기존 앱 설정의 읽기 전용 확인, 기존 NH 연결을 통한 CMA 잔고 조회를 명시적으로 승인했다. 주문·실제 장부 반영·운영 활성화·배포는 승인하지 않았다. 이번 승인 범위의 조회는 완료했다.

## 실행과 확인

지정 Lightsail 인스턴스 `portfolio-rebalancer`(ap-southeast-2)의 실행 상태와 임시 SSH 자료를 공식 AWS MCP로 확인했다. AWS가 제공한 호스트 키를 고정하고 strict host key checking으로 접속했다. 임시 개인키·인증서는 비공개 파일에만 보관하고 현재 로컬 사용자 전용 권한을 적용했다. 기존 `portfolio-api.service`의 실행 환경에서 앱 인증을 메모리로만 사용했다. NH 키/토큰을 별도 공급하거나 새 NH 클라이언트를 만들지 않았다.

첫 SSH 과정에서는 실행 중인 앱의 `/api/auth/verify`에 로그인하고, 정확히 ‘미래 성장포트’에 속한 CMA 한 계좌를 선택한 뒤 **기존 `/api/sync/namuh/compare`를 1회** 호출했다. 앱 로그인과 잔고 대조 모두 HTTP 200이었다. 정상 운영 중인 동일 앱 프로세스의 NH 클라이언트/토큰 캐시를 사용했다. 기존 클라이언트 내부의 정상 토큰 갱신 발생 여부는 조사하지 않았으며 ‘별도 토큰 발급 요청 없음’과 구분한다.

## 사용자의 400만원 이동 확인과 후속 기록

사용자는 오늘 CMA에서 **다른 포트폴리오 계좌로 4,000,000원을 이동**했다고 확인했다. 이어서 **앱에 직접 기록했다**고 알렸으며, 어시스턴트가 처리하면 기록이 꼬일 수 있다는 우려를 밝혔다.

따라서 해당 거래는 이미 사용자가 처리한 것으로 인계한다. 어시스턴트는 실제 입출금/이체/이자를 입력·취소·재입력하지 않았으며 앞으로도 이 스냅샷을 근거로 재처리하지 않는다. 사용자 기록 이후에는 추가 외부 조회를 하지 않았으므로 최신 장부와 예수금 반영 결과를 실제로 확인했다는 주장을 하지 않는다.

다음 계산은 읽은 스냅샷과 사용자 설명을 연결하는 **참고 계산**이다.

- 기록 전 장부 38,036,748원 − 이동 4,000,000원 = 34,036,748원.
- NH 대조 34,074,558원 − 위 금액 = **37,810원 차액 후보**.
- 어제 알림 38,072,203원 − 기록 전 장부 38,036,748원 = 35,455원.
- 현재 NH 대조 34,074,558원 + 이동 4,000,000원 − 어제 알림 38,072,203원 = **2,355원 증가분**.

이는 다른 미기록 자금 이동이 없고 두 잔액의 조회 기준이 비교 가능하다는 전제의 계산이다. 출금가능금액과 기존 정규화 대조 금액이 동일한 총잔고 기준인지 아직 실증하지 않았으므로 이자로 최종 확정하지 않는다. 과거 날짜별 이자를 임의로 나누거나 금리·세금·미지급 이자를 추정하지 않는다. 실제 이자 기록은 **0건**이다.

## 이번 조회로 확인하지 못한 부분

운영 버전은 `7efe40f`이며 기존 대조 API는 현금·CMA 상품 등을 합한 정규화 금액만 반환했다. 새 전용 코드의 `cma_evidence`는 반환되지 않았다. 따라서 실제 `dca`, CMA 상품 평가액, 출금가능금액 필드를 구분하거나 준비 프로필의 실제 업무 성공 봉투를 확인한 것은 아니다. 일반 보유종목 0건도 현금 반환이나 CMA 상품 0원이라는 증거가 아니다.

SSH에서 새 NH 클라이언트를 만들어 조회하거나 실행 중인 프로세스의 NH 토큰을 추출하지 않았다. 원본 응답을 얻기 위한 서버 코드 교체·임시 패치·서비스 재시작·진단 기능 배포도 하지 않았다. 이 제약을 우회하지 않고 실제 필드 의미 검증을 남겨 둔다. 저녁 19:12였다는 이유로 전환 완료나 반환 상태를 추정하지 않는다.

## 검증과 정리

새 `scripts/cma_server_readonly.py`는 SSH stdin으로 실행하는 읽기 전용 도구다. 허용한 POST는 기존 앱 로그인과 기존 잔고 대조뿐이며, 이력 모드는 NH 대조를 반복하지 않는다. 애플리케이션 모듈을 새로 import하거나 운영 DB에 직접 접속하지 않는다. 시크릿은 원격 프로세스 메모리에만 사용하고 출력/결과 파일에는 넣지 않는다.

합성 로컬 시험 **92개 통과**. 새 시험에서는 읽기 전용 요청 범위, 로그인 실패/복수 CMA/조회 실패 시 무재시도, 인증값/계좌번호/원본 메모 비노출, 이력 조회 모드의 NH 미호출을 검증했다. 별도의 합성 장부에서 400만원 이동을 기록하기 전에는 이자 반영을 차단하고, **시험 DB에서만** 이동을 먼저 반영하면 차액 37,810원이 외부 입금이 아닌 이익으로 계산됨을 확인했다. 실제 장부와 연결하지 않았다. 제품 구현·프런트엔드 변경은 없으므로 직전에 통과한 전체 백엔드 455/프런트엔드 191·빌드·격리 PostgreSQL 14항목을 반복 실행하지 않았다.

사용한 임시 SSH 개인키·인증서·호스트키 파일과 빈 디렉터리를 삭제했고 RSA 전달 키 등의 메모리 참조도 정리했다. 서버에 원격 스크립트 파일을 저장하지 않았으며 `python -I -B -`로 stdin 실행했다. 이번 작업은 전부 CMA 전용 작업 폴더에서 했고, 원래 미국 주식 폴더는 수정하지 않았다. 실제 장부 쓰기·주문·운영 설정/서비스 변경·활성화·배포·커밋은 **모두 0회**다.
