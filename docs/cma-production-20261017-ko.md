# CMA 이자 실제 반영·자동 운영·배포 완료

2026-10-17 한국 시간. 사용자가 CMA 명세 신뢰 등록, 최신 조회에 따른 초기 누적 이자 정리, 향후 자동 장부 반영, main 병합과 배포를 명시 승인했다. 만료된 AWS 기존 프로필 `hammol`의 재로그인도 별도로 승인받아 완료했다. 실제 매매·주문·계좌 이체는 하지 않았다. 이 보고서는 이전 문서의 미승인·미배포·자동 비활성 설명보다 우선한다.

## 반영 결과

대상은 **미래 성장포트의 CMA ‘현금저장소’**다. 기존 NH 연결과 실행 앱의 토큰 캐시를 사용했으며 별도 NH 클라이언트/토큰 실행기를 만들지 않았다.

| 구분 | 실제 반영 금액 | 기록 기준 |
|---|---:|---|
| 초기 누적 이자 | 35,455원 | 10월 17일 초기 수익 인식. 과거 지급일은 미지정 |
| 10월 15일 지급 이자 | 2,355원 | 세전 2,765원 − 실제 세금 410원 |
| 10월 16일 지급 이자 | 2,097원 | 세전 2,467원 − 실제 세금 370원 |
| 합계 | **39,907원** | 외부 입금이나 매매로 처리하지 않음 |

장부 잔액은 **33,936,748원 → 33,976,655원**으로 변경됐다. 초기 누적분만 먼저 반영한 뒤 새 NH 조회·장부 토큰으로 지급일별 두 건을 별도 반영했다. 초기 정리와 일일 반영 요청을 각각 다시 보내도 같은 결과가 반환됐고 현금이 추가로 늘지 않았다. 반영 후 새 조회에서도 명세/장부가 일치하고 미반영 지급 이자는 0원이었다.

현재 NH 예수금은 0원이며 CMA 상품 평가액은 33,979,122원이다. 이 중 **2,467원은 아직 지급되지 않은 평가 차이**다. 실제 매수 원금 33,976,655원과 별도로 구분하며 지급 이자로 장부에 올리지 않았다. 출금가능금액 33,978,752원도 이자 확정 기준으로 사용하지 않는다. 앱 패널에서 상품 평가액, 지급 완료 기준 잔액과 지급 확인 전 평가 차이를 구별한다.

초기 누적분은 오늘 지급된 이자로 표시하지 않고 별도 초기 수익으로 기록한다. 발생일을 알 수 없는 과거 지급일·세금·금리는 추정하지 않는다. 기존 성과 기준선·과거 마감·종가도 다시 쓰지 않았다. 기간 성과는 기존 장부/NAV 경로로 반영하며 수익을 두 번 더하거나 외부 투자금으로 빼지 않는다. 7번 탭 그래프의 현금 제외 변경은 계속 보류다.

## 자동 운영

- 해당 계좌의 일일 확인과 자동 장부 반영을 켰다. 한국 시간 **09:00·12:00·15:40**, 하루 최대 3회 확인한다.
- 실제 지급일별 순이자 상한은 **10,000원**이다. 여러 지급일을 따라잡을 때도 지급일별 합계를 대조한다. 상한 초과·미기록 자금 이동·원금/세금 불일치는 반영을 보류한다.
- 동일한 지급 완료 기준 잔액을 1분 이상 간격으로 두 번 확인하고 은행 명세와 실제 장부가 일치해야 자동 반영한다. 현금이 0원이어도 거래 명세의 보유 원금, 실제 잔고 수량·매수금액·평가손익이 모두 일치하면 지급 완료분을 검증한다. 수량 자체를 원화로 환산하지 않는다. 미지급 평가 차이를 이자로 추정하지 않는다.
- 마지막 처리일부터 최대 30일의 미반영 지급일을 대조하고 기존 이자는 재반영하지 않는다. 초기 정리 인식일보다 앞선 지급일도 초기 정리 명세의 시작일을 보존하므로 누락되지 않는다.
- **09:29:01 KST 실제 스케줄러의 첫 실행이 `NO_CHANGE`로 정상 종료**했다. 이미 반영한 지급 건을 다시 기록하지 않았다. 다음 신규 지급 건의 실제 자동 저장은 그 명세가 발생한 뒤 확인할 수 있으며, 아직 발생하지 않은 미래 실행을 완료했다고 주장하지 않는다.
- 서버 설정: `CMA_INTEREST_ENABLED=1`, `CMA_INTEREST_WRITES_ENABLED=1`, 진단 기능 `0`. 해당 계좌 외의 자동 반영 설정은 임의 활성화하지 않았다. 기존 종가 스케줄러도 켜진 상태를 보존했다.

5번 탭 기록 입력 영역의 **CMA 잔고·이자 확인**에서 잔고 구분, 초기 누적 정리 이력, 지급일별 이력과 일일 확인 상태를 볼 수 있다.

## 검증과 복구

- 최종 전체 백엔드 **583 통과, 기존 5 제외**. 프런트 전체 및 최종 로컬 빌드 통과. 격리 PostgreSQL 21항목 통과 후 종료. 지급 원금·미지급 평가 차이 분리와 주말 지급일 처리는 추가 로컬 시험 및 실제 운영 명세/장부 대조로 검증했다.
- 서버 감사·비공개 백업·고정 요청/결과: `/var/backups/portfolio-rebalancer/cma-20261017-8aeb8a7`. 앞선 진단/전환 백업도 보존했다. 환경 설정과 금융 테이블 JSONL 스냅샷이며 **전체 pg_dump 복원 아카이브는 아니다**.
- 코드 복구: 위 폴더의 `rollback.sh`로 직전 코드 및 자동 비활성 상태로 복귀할 수 있다. CMA 이전 기준 코드는 `/opt/portfolio-rebalancer/releases/fafd90c`에도 보존했다. 코드 복구는 승인된 이자 기록을 자동 취소하거나 DB를 과거로 덮어쓰지 않는다.
- 이자 기록 취소는 현재 장부 토큰과 후속 변경 여부를 검사한다. 여러 지급일을 일괄 반영한 건은 전체 묶음으로 취소하며 자동 정책을 끈다. 초기 정리 취소도 후속 기록이 있으면 먼저 해당 기록을 확인해야 한다. 실제 취소나 전체 DB 복원은 이번 완료 과정에서 실행하지 않았다.
- 실제 운영 감사 결과는 서버 `final.json`, 로컬 실행 자료는 ignored `backups/cma-release-20261017`에 보관한다. 임시 SSH 키·인증서·host 파일은 작업 종료 시 삭제하며 기존 AWS 로그인 프로필과 앱의 NH 설정은 보존한다.
