## 5. 필요한 다음 승인과 검증 절차

현재 승인은 로컬 준비까지이므로 여기서 멈춘다. 다음 승인은 다음 내용을 함께 묶어 받을 수 있다.

> 진단 전용 변경의 AWS 적용과 필요한 서비스 재시작, 기승인한 임시 SSH/기존 앱 인증 활용, 해당 CMA의 기존 NH 잔고 읽기를 승인한다. 조회는 승인 후 48시간 이내 하루 최대 3회·총 최대 6회로 제한한다. CMA 자동 반영·장부 변경·주문·운영 DB 마이그레이션은 승인하지 않는다.

이 횟수와 기간은 **승인 검토용 제안**이며 현재 승인이나 실행 예약이 아니다. 새 인증정보·계좌번호를 채팅에 제공할 필요는 없다. 기존 인증을 이용할 수 없거나 적용 기준 버전이 달라졌다면 먼저 그 상태를 보고한다.

승인 후 절차:

1. 현재 운영 버전/파일 해시 확인 → 진단 전용 변경만 적용 → 기본 인증과 기존 기능 정상 여부 확인. 주문이나 장부 수정 경로를 시험하지 않는다.
2. 반환된 현금이 보이는 낮 시간과 예수금이 전환되는 저녁 시간 등 서로 다른 상태에서 제한 횟수 안에 관측한다. 정확한 전환 시각을 미리 단정하지 않는다. 현재는 모니터나 자동 예약을 만들지 않았다.
3. `dca`, `nxt2_dd_dca`, `drn_pbl_amt`, CMA/RP 상품 평가액의 관계와 성공 응답 구조를 대조한다. 각 관측 후 장부 불변 여부를 확인한다. 예수금 0원을 출금·손실로 처리하지 않는다.
4. 지급 이자·거래 명세를 기존 NH API에서 얻을 수 있는지 확인한다. 실제 계약과 응답 근거가 있는 항목만 정규화한다. 임의의 API 경로·필드·금리·세금을 추정하지 않는다. **추가 거래 명세 API 호출이 필요하면 위 잔고 조회 승인과 별도로 호출 범위를 정한다.**
5. 근거가 확보되면 실응답을 비식별 시험 자료로 바꾸고, 명세 수집/정규화와 검증 형식 등록을 로컬에서 마무리한다. 근거를 확보할 수 없으면 자동 반영을 차단한 상태로 유지하고 확인 가능한 범위를 보고한다.
6. 읽기 검증을 마치면 진단 플래그를 끄거나 이전 릴리스로 복귀한다. 배포·서비스 변경 승인은 이 적용/복구까지 포함하며, 실제 실행 시 변경 전 상태를 보존한다.

## 6. 자동 반영 완성까지 남는 단계

잔고 읽기 성공만으로 매일의 이자 금액이 확정되지는 않는다. 실제 NH 지급 이자/거래 명세의 제공 여부·완전성·순액 의미가 아직 확인되지 않아 **실제 NH 명세 수집기는 미완성**이다. 현금과 상품의 전환 방식도 실제 필드 기준으로 검증해야 한다. 이 부분은 이번 로컬 개발로 확인했다고 주장하지 않는다.

명세 근거 확인 뒤에는 실제 형식의 수집/정규화와 실자료 회귀 시험, 초기 누적 차액의 별도 처리안이 필요하다. 이후에야 대상 계좌·최대 자동 이자액·조회 시각·실패 처리·초기 차액 처리·DB 변경을 포함한 운영안을 확정할 수 있다. **실제 장부 반영, CMA 자동 기능 운영 활성화 및 전체 기능 배포는 그때 별도 승인을 받아야 한다.** 현재 준비한 진단 전용 묶음은 그 승인을 대신하지 않는다.
