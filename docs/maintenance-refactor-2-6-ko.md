## 2. 조회 범위 최적화 — 로컬 검증 완료

- 전체 요약은 기존 기본 동작을 유지. 개별 현황은 해당 포트폴리오의 계좌·종목·보유·전체 매매 이력만 읽음.
- 상단 선택기에 필요한 전체 포트폴리오 목록은 유지. 매수 원가 때문에 과거 날짜를 자르지 않음.
- 초기 거래일 계산을 종목마다 반복 검색하는 대신 계좌·종목별로 먼저 집계.
- 과거 그래프의 확정 평가 기록은 불필요한 재구성 자료를 조회하지 않음. 미확정·누락값은 그대로 유지.
- 새로운 인덱스·스키마·운영 설정 변경 없음.

전용 로컬 PostgreSQL 17.6 / 합성 2개 포트폴리오, 계좌·종목 각 252개, 거래 7,560개:

## 3. 과거 배당 계산 재사용 — 로컬 검증 완료

- 요청 단위의 계좌·종목별 배당 수량 인덱스를 재사용하고, 같은 날짜의 과거 근거 확인 결과도 재사용.
- INIT은 기존 배당 엔진의 당일 마감 수량 의미를 유지. 배당락일 당일 매매는 포함하지 않음.
- 최초 INIT 이전의 수량은 기존 Python `sum()` 연산 순서까지 보존하고 날짜별 결과를 재사용. 소수 수량의 원시 반환값도 같게 유지.
- 순서가 섞인 거래·배당, 중복 초기잔고, 소수 수량 등을 포함한 300개 합성 사례에서 전체 반환값이 기준 함수와 정확히 일치.
- 합성 과거 16개 관측일이 같은 계좌·종목 인덱스를 1회 생성하는 것을 검증. 관련 63개 테스트 통과.
- CPU 합성 벤치마크: 거래 1,000개 / 관측일 120개. 기존 1,080.291ms → 41.669ms(각 5회 중앙값), 정렬 120회 → 1회. 전체 결과 SHA-256 동일.
- 벤치마크는 운영 지연 시간 또는 모든 데이터에서의 개선율을 의미하지 않음.

## 4. 매매 입력 공통화 — 로컬 검증 완료

- PC·모바일의 계좌·종목·수량·단가·행 삭제 입력을 `TradeRowInputs`로 공통화. 매수와 매도가 같은 제어된 입력 컴포넌트를 사용.
- 계좌·종목·달러 원가 및 허용 종목을 한 번 분류해 반복 `find`/`filter`를 줄임. 기존 첫 일치 항목과 종목 순서를 보존.
- 매수·매도의 행 수정 규칙은 순수 함수로 공통화. 수동 단가·환율·명시 수수료, 임시 입력 및 미확정 재시도 상태의 규칙은 유지.
- 새로 고정한 4개 폼 상태 및 기존 전체 화면 17개에서 렌더링 출력 해시가 변경 전과 동일. 화면 디자인·문구·조작 순서 변경 없음.
- 프런트엔드 전체 261개 테스트, 경고 없는 린트, 배포용 빌드 통과.
