- 새로운 인덱스·스키마·운영 설정 변경 없음.

전용 로컬 PostgreSQL 17.6 / 합성 2개 포트폴리오, 계좌·종목 각 252개, 거래 7,560개:

## 3. 과거 배당 계산 재사용 — 로컬 검증 완료

- 요청 단위의 계좌·종목별 배당 수량 인덱스를 재사용하고, 같은 날짜의 과거 근거 확인 결과도 재사용.
- INIT은 기존 배당 엔진의 당일 마감 수량 의미를 유지. 배당락일 당일 매매는 포함하지 않음.
- 최초 INIT 이전의 수량은 기존 Python `sum()` 연산 순서까지 보존하고 날짜별 결과를 재사용. 소수 수량의 원시 반환값도 같게 유지.
- 순서가 섞인 거래·배당, 중복 초기잔고, 소수 수량 등을 포함한 300개 합성 사례에서 전체 반환값이 기준 함수와 정확히 일치.
- 합성 과거 16개 관측일이 같은 계좌·종목 인덱스를 1회 생성하는 것을 검증. 관련 63개 테스트 통과.
- CPU 합성 벤치마크: 거래 1,000개 / 관측일 120개. 기존 1,080.291ms → 41.669ms(각 5회 중앙값), 정렬 120회 → 1회. 전체 결과 SHA-256 동일.
- 벤치마크는 운영 지연 시간 또는 모든 데이터에서의 개선율을 의미하지 않음.

## 4. 매매 입력 공통화 — 로컬 검증 완료

- PC·모바일의 계좌·종목·수량·단가·행 삭제 입력을 `TradeRowInputs`로 공통화. 매수와 매도가 같은 제어된 입력 컴포넌트를 사용.
- 계좌·종목·달러 원가 및 허용 종목을 한 번 분류해 반복 `find`/`filter`를 줄임. 기존 첫 일치 항목과 종목 순서를 보존.
- 매수·매도의 행 수정 규칙은 순수 함수로 공통화. 수동 단가·환율·명시 수수료, 임시 입력 및 미확정 재시도 상태의 규칙은 유지.
- 새로 고정한 4개 폼 상태 및 기존 전체 화면 17개에서 렌더링 출력 해시가 변경 전과 동일. 화면 디자인·문구·조작 순서 변경 없음.
- 프런트엔드 전체 261개 테스트, 경고 없는 린트, 배포용 빌드 통과.

## 5. 리밸런싱 계산 단계 분리 — 로컬 검증 완료

- 공개 함수는 입력 정리와 단계 호출을 담당. 목표 수량 → 매도 → 자금·한도 → 매수 배분 → 이체 → 예상 자산을 내부 함수로 분리.
- 종목·계좌·계좌별 보유를 인덱스로 재사용. 첫 일치 항목, 계좌 우선순위, 기존 ID 비교 방식 및 합산 순서를 유지.
- 매수 배분 알고리즘, IRP 한도, 예금 잠금, 금액·수량 반올림 및 이체 문구는 변경하지 않음.
- 무작위 합성 150개 사례와 기존 회귀 사례 등 161개 테스트 통과. 전체 반환값이 보존한 이전 함수와 정확히 일치하고 입력 자료도 불변.
- 합성 종목 80개·계좌 24개·보유 1,130개에서 5회 중앙값 141.337ms → 68.363ms, 전체 반환값 SHA-256 동일. 운영 성능 보장은 아님.

## 6. 거래 저장 책임 분리 — 로컬 검증 완료

- 실제 체결일, 종목·계좌·통화, 알림 가져오기 검증 및 보유 수량·평균 원가·취득환율 계산을 `logic/trade_entry.py`의 순수 함수로 분리.
- `execute_trade`는 SQL 실행과 거래 경계에 집중. 연결 임대·반환, 계좌 잠금, 원가 정정 제한, 묶음 저장·중복 방지, commit/rollback 순서 및 오류 메시지를 유지.
- 기록 재생(replay)과 새 거래 입력의 기존 INIT 반올림 차이를 통합하거나 바꾸지 않음. 관리형 달러 원가 경로는 기존 모듈을 그대로 호출.
- 관련 기존 회귀 테스트 92개 통과.
- 전용 PostgreSQL에 변경 전·후 합성 DB를 각각 만들고 정상 거래 14개·거절 사례 7개를 순서대로 실행. 국내 매수·부분/전량 매도·재매수, 과거일 매수, 달러 초기잔고·매수·매도, 관리형 달러 원가, 추정/명시 수수료, 알림 중복을 포함.
- 각 단계의 모든 금융 테이블 내용 및 SQL·commit/rollback·연결 반환 순서가 동일. 서로 다른 DB의 자동 생성 시각만 정규화하며 거래일·환전일·금액·수량·원가·비용·식별값은 그대로 대조.
- 실패한 단건과 두 번째 행이 실패한 묶음은 테이블 지문이 실행 전과 동일. 삭제 후 재생 결과도 동일.
- 같은 요청 2건의 동시 재시도는 영수증 1건·거래 1건·예수금 차감 1회만 발생.
- PostgreSQL의 실제 잠금 대기 상태를 관찰하고 잠금 해제 후 저장 성공을 확인. 마지막 1주를 동시에 매도하는 2건 중 1건만 성공하고 잔량 0주 유지.

## 남은 사항과 범위 제한

- 승인 범위 2~6의 로컬 구현 및 가능한 합성 검증을 완료. 별도 제품·회계 기준 결정이 필요한 항목은 발생하지 않음.
- 운영 자료로 속도를 측정하지 않았으므로 실제 첫 조회 지연의 개선 폭은 미확인. 외부 시세 수집 지연을 이 리팩토링으로 모두 해결한다는 의미는 아님.
- 새로운 DB 인덱스·테이블·역할·스키마 변경, 서버 규모·설정 변경 및 의존성 업그레이드는 포함하지 않음.
- main 반영과 운영 배포·검증은 사용자가 2026-11-01 별도 승인했다. 실제 배포의 전후 대조 결과는 Git 제외 릴리스 증거 폴더에 기록한다.

## 2026-11-01 배포 검증 중 발견한 달력 동시성 보완

- 서버 재시작 직후 종가 수집 스레드와 기간 성과 조회가 거래소 달력을 동시에 처음 생성하면서 pandas 내부의 값·날짜 인덱스 길이 불일치 오류가 발생했다. 검증 도구가 이를 감지해 기존 버전으로 자동 복구했다.
- 보호 대상 28개 테이블 및 원본 기간 성과는 그대로였으며, 같은 자료로 직접 비교한 새·기존 보유 손익 그래프와 실현손익 계산 결과도 모두 일치했다.
- `lru_cache`만으로는 동시 cache miss의 중복 생성을 막지 못한다. `close_calendar.calendar()`의 라이브러리 생성 호출에만 재진입 잠금을 적용했다. 생성된 달력 재사용, KRX·미국 개장일·휴장일·종가 시각·수익률 정의는 유지한다.
- 동시 초기 생성 직렬화, 실제 오프라인 KRX·미국 달력 병렬 조회, 생성 실패 후 재시도 등 3개 검증을 추가했다. 달력·종가·보유 성과 관련 35개 테스트 통과.
