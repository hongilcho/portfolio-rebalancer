# 종가 기준 기간 성과

백엔드가 KRX 거래일 한국 시간 16:00에 종가 평가액을 저장합니다. 앱 조회와 무관하게 실행되며 조회는 기록을 덮어쓰지 않습니다. 마감이 늦춰진 날은 정규장 마감 30분 후 실행합니다. 내부 스레드가 30초마다 예정 작업을 확인하므로 정상 상태에서 실행 시각에 최대 약 30초의 차이가 있습니다. 별도의 OpenAI 자동화·Render Cron 서비스는 필요하지 않습니다.

## 평가 기준

- 국내 주식·ETF: 명시적인 KRX 일별 차트에서 해당 거래일 종가. 네이버 실패 시 Yahoo 일봉의 비수정 `Close`를 사용합니다. 조정 종가나 시간외 시세는 사용하지 않습니다.
- KRX 금현물 `M04020000`: 금현물 거래 종료 상태와 날짜를 확인한 일별 종가만 사용합니다. 금선물·임의 기본값으로 대체하지 않습니다.
- 미국 주식·ETF: 한국 평가 예정 시점까지 마감한 가장 최근 미국 정규장 종가. 미국 휴일·서머타임을 반영하며 가격 날짜를 보존합니다. 현재 VT·PDBC의 시장 일정은 XNYS 달력을 따릅니다.
- 환율: 수집일 당일의 하나은행 고시환율(네이버 제공). 고시 시각·수집 시각을 별도 보존합니다. KRX 15:30의 정확한 환율 또는 달러/원 외환시장 종가를 의미하지 않습니다. 수집 장애 시 성공한 최초 고시환율을 고정합니다. 과거 날짜를 복구할 때 당일 수집 환율이 없으면 복원하지 않습니다.
- 예금: 평가 날짜의 세후 원리금. 기존 365일 이자·세금 내림 방식과 동일합니다.
- 수량·예수금: **최초 수집 당시 앱 장부**. 16시 이전에 실제 체결·예수금 변동을 반영해야 합니다. 백엔드가 늦게 실행되면 장부 수집 시각도 늦어지며, 이 시각을 화면에서 확인할 수 있습니다.
- 평가액과 함께 수집 시점의 누적 순입금·손익·입출금 revision을 원본에 보존합니다. 화면의 손익·기간 수익률은 저장 평가액과 최신 입출금 기록으로 재계산합니다. 배당은 실제 예수금에 반영된 금액만 포함하며 계산 배당을 재합산하지 않습니다.

종가 수집 당시의 장부·환율·가격·종목별 가격 날짜·출처를 DB에 보관합니다. 일반 API는 장부 전체 대신 작은 메타데이터만 제공합니다. 다른 포트폴리오와 가상자산은 합산하지 않습니다.

## 재시도·복구·정정

`performance_close_jobs`의 포트폴리오/날짜별 기본키, 행 잠금 및 10분 DB lease로 여러 서버·배포가 겹쳐도 작업 소유자를 구분합니다. 외부 통신 중 DB 트랜잭션을 유지하지 않습니다. 원가·거래·예수금을 수정하는 동작은 없습니다.

장부와 환율을 먼저 보존하고, 개별 종가 수집이 성공할 때마다 보관합니다. 실패하면 이전 평가 기록을 유지하고 5분 간격으로 재시도합니다. 프로세스가 종료되어도 DB에 저장된 입력으로 이어서 수행합니다. 성공한 FX·개별 가격은 재시도 시 다시 수집하지 않습니다. 오래된 작업의 lease가 인계되면 기존 작업자는 결과를 발행할 수 없습니다.

종가 완료 이후 늦게 입력한 **당일** 거래·잔고는 6번 탭의 `기록 관리·수집 상태`를 펼쳐 `오늘 종가 기록 재시도·장부 반영`으로 반영합니다. 기존 종가·환율은 유지하고 장부만 새로 읽습니다. 새로 보유한 종목에 기존 종가가 없으면 해당 날짜 종가를 추가 수집합니다. 이전 평가 기록은 `performance_snapshot_revisions`에 보존하고 최신 평가액으로 성과를 자동 재계산합니다. 최초 수집 실패 중에는 최초 장부를 유지하므로, 성공 후 같은 버튼으로 늦은 거래를 반영합니다.

과거 날짜의 자료가 없는 경우 현재 장부나 환율로 추정하지 않고 `missed`로 표시합니다. 서버가 하루 전체 중단된 날은 자동 복원하지 않습니다. 당일 장부·환율을 확보한 작업만 다음날 이후에도 종가를 재시도할 수 있습니다. 지나간 날짜의 장부를 수정하는 UI는 이 범위에 포함하지 않습니다.

기존 조회 기록은 `legacy_view`, 새 시작 기준은 `baseline`, 종가 기록은 `close`로 구분합니다. 기존 조회 기록을 종가로 바꾸지 않습니다. 같은 날짜에 종가가 새로 저장되면 기존 값은 변경 이력에 보존됩니다. 기준을 16시 이후 등록하면 다음 거래일부터 수집합니다. 기존 사용자의 자동 수집은 이 기능 배포일부터 시작합니다.

## 그래프·월말 경계

기본 화면은 그래프와 표 위주로 표시하고 수집 상태·설명·상세는 펼쳐 봅니다. 외부 입출금 기록이 없으면 입출금 없음으로 계산하며 기록된 입출금은 날짜·금액을 자동 반영합니다. 매일 입출금을 확인하는 버튼은 없습니다. 추가·취소·복원 뒤에도 즉시 재계산하며, 순입금이 0이라도 서로 다른 날짜의 입금/출금은 각각 계산에 반영합니다. 입출금이 반영된 기간은 그래프 아래에 건수를 표시합니다. 과거 확인 정보와 API는 호환성을 위해 유지하지만 수익률 계산의 조건으로 사용하지 않습니다.

연속 KRX 거래일의 종가 점은 선으로 연결합니다. 주말·휴장일은 건너뛰고 누락된 거래일에는 선을 끊습니다. 기존 조회 기록은 기존 날짜 단위 연결을 유지하며 점의 상세에서 평가 기준을 표시합니다.

종가 기록의 월말·연말 경계는 그 날짜 이하의 마지막 KRX 거래일입니다. 그 정확한 거래일이 미기록이면 앞선 다른 거래일로 대체하지 않습니다. 기간 시작/종료와 입출금 계산 범위도 실제 평가 날짜를 따릅니다. 마지막 거래일 이후 휴일에 발생한 자금 흐름은 다음 평가 구간에 포함됩니다. 현재 포트폴리오의 보유자산 수익률과 기간 성과 지표는 그대로 별개입니다.

## 운영 설정과 달력 유지

`PERFORMANCE_CLOSE_SCHEDULER_ENABLED=1`이 기본값입니다. `0`, `false`, `off`는 자동 수집을 끕니다. **운영 DB에 연결하는 로컬 개발 서버는 반드시 0으로 설정합니다.** 현재 로컬 QA와 테스트는 이를 명시적으로 끄고 격리된 DB만 사용합니다. 수동 종가 재시도 API는 켜짐/꺼짐과 별개로 명시적인 요청에만 실행됩니다.

휴장일은 `exchange-calendars==4.13.2`를 기본으로 사용합니다. 이 버전에 빠진 2026-06-03 지방선거일·2026년 이후 제헌절과 2026-11-19 수능일의 1시간 마감 지연을 추가 반영했습니다. 임시 휴장일은 `PERFORMANCE_KRX_EXTRA_HOLIDAYS=YYYY-MM-DD,...`, 추가 1시간 마감 지연은 `PERFORMANCE_KRX_DELAYED_CLOSE_DATES=YYYY-MM-DD,...`로 반영할 수 있습니다. 잘못된 날짜 설정은 수집을 중지하고 달력 오류로 표시합니다. 새로운 임시 공휴일·수능일 공지는 매년 확인해야 합니다.

## 배포·검증

프런트엔드와 백엔드 배포가 필요합니다. 운영 DB 백업 후 배포합니다. 시작 시 기존 성과 테이블에 메타데이터 컬럼과 `close_started_on`을 추가하고 작업/변경 이력 테이블을 생성합니다. 기존 잔고·거래·시작 기준 값은 수정하지 않습니다. 이 기능 이전 버전은 조회 시점 저장을 수행하므로 롤백하면 종가 전용 기록 정책이 유지되지 않습니다. 장애 대응으로 자동 수집만 일시 중지할 때는 위 환경변수를 0으로 설정합니다.

자동 단위 테스트는 휴장일·수능일·미국장 날짜·종가/환율 검증·실패/재시작·누락된 과거 장부·월말 경계를 검증합니다. `python scripts/verify_closing_performance.py`는 지정된 127.0.0.1:55437의 새 합성 PostgreSQL DB에서 DDL 재실행·부분 실패·동시 작업·lease 만료·정정 이력·API 직렬화·현금/거래 불변을 확인합니다. 운영 DB에 테스트를 실행하지 않습니다.
