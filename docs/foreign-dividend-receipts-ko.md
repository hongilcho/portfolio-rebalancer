# 해외 현금 배당과 SGOV 배당 자료 보완

2026-11-06. 브랜치 `codex/foreign-dividend-receipts`, 기준 main `c1dd86e`.
완료된 CMA 작업 폴더를 재사용하며 기존 CMA·자동매수 브랜치를 보존한다.
main 병합·커밋·push·운영 배포·운영 금융 기록 입력은 수행하지 않았다.

## 사용자 흐름

1. 5번 → 기록 입력 → NH 알림 가져오기. 해외증권 권리발생 알림을 여러 건 누적 입력할 수 있다.
2. USD 현금 배당만 지원한다. 종목 티커·계좌 마스크·배정액·외화세액·수수료·실수령 달러·원화 세금을 분리한다. 주식배당·다른 권리·다른 통화는 반영하지 않는다.
3. 배당락일과 실제 지급일을 구분한다. 알림에 날짜가 없으므로 화면 날짜를 제안하며 반드시 적용 날짜를 확인한다. 공시가 없어도 사용자가 확인한 배당락일을 직접 입력할 수 있다.
4. 입금일 평가환율을 확인한다. 조회 환율은 제안값이며 실제 환전이 아니다. 실제 과거 지급일이면 그 날짜의 확인한 기준환율을 입력한다.
5. 실제 수령액과 예상 잔고·평균 취득환율을 확인한 뒤 기존 최종 확인으로 일괄 반영한다.
6. 원화 세금은 기본으로 출금 대기. 실제 출금을 확인했으면 지금 차감, 기존 장부에 이미 반영되었으면 중복 차감 안 함을 선택한다.
7. 나중에 세금이 출금되면 5번 → 기록 조회 → 해당 배당 상세 기록에서 출금일과 실제 출금을 확인한다. 세금 출금은 별도 감사 기록을 남긴다. 새로운 배당 수익이나 달러 입금을 만들지 않는다.
8. 7번 배당 상세에서 외화 실수령과 원화 세금을 별도로 표시한다.

## 회계 기준

- 실제 달러 입금과 `usd_cash_state`의 달러 잔액·원화 기준 원가를 NH 묶음의 같은 트랜잭션에서 갱신한다. 0달러부터도 시작 가능하며, 기존 달러 원가가 없거나 잔고가 맞지 않으면 기준 등록/정정 안내로 중단한다. 원가를 추측해 덮어쓰지 않는다.
- 새 평균환율 = (이전 달러 원가 + 실제 수령 USD × 확인한 입금일 환율) / (이전 USD + 실제 수령 USD).
- 원화 세금은 달러 취득원가에 섞지 않는다. 달러 원가 추적의 자산 평가 기준과 배당 수익의 세금을 분리한다.
- 다음 미국 자산 매수는 기존 공통 매매 경로에서 이 평균환율을 사용한다. 배당 등록 자체는 기존 주식 수량·매입 원가를 바꾸지 않는다.
- 배당 손익은 공시 계산의 해당 배당락일 항목을 실제 외화 수령액으로 교체한다. 기본 15% 세금을 한 번 더 빼지 않는다. 알려진 원화 세금은 원화 손익에서 한 번 차감하고, 달러 표시에서는 현재 표시 환율로 환산한다.
- 원화 세금 대기 중에도 알려진 세금을 배당 손익에서 제외한다. 실제 현금 출금 전에는 NAV에 그 현금이 남아 있으므로 보유 배당 손익과 현금 기준 기간 성과의 범위 차이가 있을 수 있다. 세금 출금 때 배당 손익을 다시 차감하지 않는다.
- 지급일 이후 공개 공시가 보완돼도 실제 수령액을 다시 더하지 않는다. 지급일 이전 역사 평가에서는 그 이후 들어온 실제 수령 기록을 사용하지 않는다.
- 배당과 세금은 외부 투자금 입출금으로 만들지 않는다. 기존 기간 성과 스냅샷을 다시 쓰지 않는다.
- 동일 요청 재시도 및 같은 계좌·종목·배당락일의 동시 저장은 한 번만 반영한다. 같은 날짜·금액의 기존 수동 달러 입금이 있으면 중복 현금 반영을 막는다. 이미 반영된 USD와 원화 세금은 각각 기록만 남길 수 있다.
- 이후 매매·환전이 있으면 앞선 배당 취소를 차단한다. 후속 기록부터 역순 취소하면 달러 예수금·원가·세금이 복원된다. 달러 매매 취소의 이진 부동소수 오차도 Decimal 복원으로 막아 checkpoint가 미세 오차로 막히지 않게 했다.

## SGOV 공개 자료

- Yahoo 응답에 최신 월 배당이 빠지면 iShares 공식 공개 분배금 표로 보완한다. 운용사 표의 배당락일·지급일·정밀 주당 금액을 보존한다. 미래 배당은 수익에 반영하지 않는다.
- 운용사 요청은 기존 24시간 배당 캐시 갱신에 포함되는 단일 요청이며 timeout 6초다. 기존 데이터가 있으면 종전과 같은 백그라운드 갱신 경로를 사용한다.
- SGOV의 최근 월 배당 간격/최근 배당일이 45일을 초과하면 불완전 상태를 표시한다. 두 소스 모두 불완전하면 정상 갱신으로 저장하지 않고 기존 캐시를 보존한다. 자산당 추가 DB 조회는 없다.
- 이 운용사 보완은 SGOV에 한정한다. 다른 종목의 월별 지급 주기를 추정하지 않는다. 해외 알림은 현재 포트폴리오의 일반 미국 상장 현금 배당을 지원한다.
- 실제 공개 페이지에서 2026-10-01 $0.300547 / 지급 10-06, 2026-11-02 $0.328581 / 지급 11-05를 해석했다. 과거 0금액 분배 항목은 현금 배당에서 제외하되 전체 수집을 실패시키지 않는다.

## 데이터·배포 범위

- 기존 NH 알림/달러 장부의 JSON payload와 이벤트를 확장한다. 새 테이블·DDL·권한·RLS·필수 환경변수는 없다.
- 기존 자료를 일괄 수정하거나 과거 배당·거래·원가·기간 성과를 덮어쓰지 않는다. 운영 접근과 증권사 호출 없이 검증했다. 개발 중 공개 운용사 페이지 확인만 수행했다.
- 이후 출시에는 프런트엔드와 AWS 백엔드 모두 필요하다. `foreign_dividend_protocol=1` 확인 전 프런트엔드는 해외 알림을 저장하지 않는다.
- 기존 금융 기록이 생기기 전에는 코드 롤백이 가능하다. 새 해외 배당 저장 후에는 구버전 백엔드가 해당 취소를 이해하지 못하므로 단순 백엔드 롤백 상태에서 쓰기를 계속하면 안 된다. 새 기록을 보존한 채 호환 코드를 유지하거나 쓰기를 중단하고 복구한다. DB 전체 복원이나 실제 기록 삭제를 자동 수행하지 않는다.

- 백엔드 전체 876 통과·기존 5 제외(기존 의존성 경고 1개). 결과와 로그: ignored `backups/foreign-dividends/backend-tests.log`.
- 프런트엔드 295 통과, 린트 경고 0, 빌드 통과.
- 전용 loopback PostgreSQL 55476에서 실제 NH 묶음 반영, 평균 원가, 후속 매수, 원화 세금, 동일 요청, 동시 중복, 중간 실패 rollback, 후속 취소 후 원상 복구를 확인했다. 운영 설정 로딩·외부 HTTP·증권사 호출 차단.
- `scripts/verify_foreign_dividends.py`는 자신의 합성 cluster를 검증하고 그 안에서만 실행한다. `--reset`은 해당 합성 DB만 재생성한다.
- 기존 `scripts/verify_nh_dividends.py` 국내 배당 PostgreSQL 회귀 검증도 별도로 통과했다. 과거 스냅샷과 외부 입출금 불변을 확인했다.
- 기준 평가 응답의 기존 해시를 그대로 유지했다. 프런트엔드 두 history 해시만 해외 배당 지원 도움말 문구 변경 때문에 명시적으로 갱신했다. 다른 화면의 기준값은 유지한다.
- 화면 예시: http://127.0.0.1:5209/dev/foreign-dividends/index.html . 실제 입력·조회·세금 컴포넌트를 사용하되 운영 API는 모두 차단한다. 저장은 메모리상 합성 예시이며 실제 DB 검증은 별도 PostgreSQL 결과를 근거로 한다.
