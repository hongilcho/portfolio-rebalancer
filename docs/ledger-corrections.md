# 장부 확인 및 정정

구현 브랜치: codex/ledger-reconciliation. 운영 데이터에는 적용하지 않았다.

## 화면과 사용법

- 1번 현황은 조회 전용. 나무 잔고 덮어쓰기와 예수금·수량·평단가 직접 수정 버튼을 제거했다.
- 4번 기록 입력 아래 접힌 **장부 확인 및 정정**에서 계좌와 종류를 선택한다.
- **과거 출금 누락**: 성과 기준일 이전에 실제 출금했으나 현재 예수금에 누락된 경우. 발생일·금액·사유를 입력한다. 현재 예수금을 차감하되 기준일 이후의 새 외부 출금으로 기록하지 않는다.
- **예수금 정정·초기 잔고**: 실제 잔고를 입력한다. 달러 잔고는 확인한 평균 취득환율도 입력한다. 달러 현금 원가와 기존 미국 종목 원가는 별개다.
- **수량·평단가 정정·초기 보유 등록**: 확인한 실제 수량, 배당 차감 전 단가, 미국 종목의 달러 단가·매입환율, 배당 시작일·수동 보정을 입력한다. 매수로 처리하거나 예수금을 차감하지 않는다. 실제 매매는 기존 매수·매도 입력으로 기록한다.
- 변경 전후 미리보기, 과거 평가 기록 검토, 최종 확인을 거쳐 저장한다. 저장 결과가 불명확하면 같은 요청으로 재확인한다. 확정 전에는 다른 4번 탭 입력을 막는다.
- 5번 계좌 설정은 이름·종류·한도 등 설정만 편집한다. 신규 계좌는 예수금 0으로 생성 후 4번에서 초기 잔고를 등록한다. 한도 소진 체크는 5번으로 이동했다.
- 3번 리밸런싱 이체 계획은 모의 계획이다. 실제 이체는 4번에서 양쪽 계좌를 기록한다.

## 과거 성과

발생일 이후 저장된 기록마다 다음을 직접 선택한다. 같은 날짜의 시작 기준과 평가 기록은 별개의 기록이다.

1. 같은 오차 포함: 당시 계좌 예수금·보유 수량과 환율·종가를 근거로 해당 평가액만 보정한다.
2. 이미 정상인 기록: 해당 기록은 유지한다.
3. 확인하지 못함: 현재 장부 정정은 저장하되 해당 기준/평가액에 의존하는 손익·수익률은 미확정으로 표시한다.

장부나 가격 근거가 부족하거나 보정 후 잔고/평가액이 음수가 되는 기록은 자동 보정할 수 없다. 임의로 모든 날짜에서 출금액을 차감하지 않는다. 미확정 기록은 정정 목록 또는 기록 조회에서 나중에 확인할 수 있고 현재 잔고를 다시 차감하지 않는다. 수량 변동 없는 평단가·배당 보정은 기간 평가액 자체를 바꾸지 않는다.

취소는 가장 최근 정정부터 한다. 후속 매매·환전·입출금 또는 해당 과거 성과 기록의 후속 변경이 있으면 직접 취소를 거절하고 새 정정을 안내한다. 정정 기준 INIT와 정정 이전 매매·환전의 직접 취소를 차단한다. 보유 원가 정정 이후 그 종목에 더 과거 날짜의 매매를 추가할 수 없다.

## 나무 API 대조

조회 전용이다. 선택 계좌의 제공된 예수금·종목만 비교한다. 결과를 정정 초안으로 가져와도 저장 전후 확인은 따로 필요하다. 제공되지 않은 종목을 자동으로 수량 0으로 추정하지 않는다. ISA·IRP·연금저축 미지원은 그대로다. 원가에 대한 해석이 다를 수 있어 증권사 평단가로 자동 덮어쓰지 않는다. 실제 나무 API 호출은 이번 검증에서 수행하지 않았다.

## 저장과 배포

ledger_adjustments 신규 테이블에 발생일/등록 시각, 사유, 요청, 현재 장부 전후, 과거 기록 검토, 취소 상태를 저장한다. 과거 평가액 수정·취소 전 원본은 performance_snapshot_revisions에도 보존한다. 현재 장부와 과거 성과 수정은 하나의 DB 트랜잭션이다. 요청 ID와 장부 지문으로 중복 제출·오래된 미리보기를 차단한다. 종가 작업과 동일한 잠금 순서를 사용한다.

기존 잔고 덮어쓰기 API는 410, 계좌 설정의 예수금 변경은 거절한다. 기존 달러 RECONCILE API 역시 새 정정 화면으로 안내하며, 시작 기준 OPENING과 실제 환전·입출금은 유지한다. 원화 수동 출금도 예수금에 함께 반영할 수 있도록 수정했다.

이 기능은 프런트엔드와 백엔드 배포가 모두 필요하다. 백엔드의 기존 init_db 경로에서 새 테이블을 생성한다. 사용자 승인 전에는 main 병합·push·운영 배포를 하지 않는다. 기존 운영 잔고에 자동 정정은 없다. 기능 코드 롤백은 입력을 멈추고 이전 프런트/백엔드 버전으로 되돌린다. 정정 데이터나 테이블은 삭제하지 않는다. 장부 자체를 되돌릴 때는 새 버전의 정정 취소/새 정정을 사용하고, 후속 기록이 있다면 현재 상태를 보존한 채 별도 복구 계획을 세운다. 기존 버전은 신규 정정에 대한 취소 보호를 모르므로 정정 후 옛 매매/환전 취소 기능 사용은 피한다.

Supabase 보안 작업은 사용자 요청에 따라 계속 보류한다. 신규 테이블의 RLS·공개 API 역할 권한 제한은 이번 기능 코드에 추가하지 않았다. 운영 반영 전에 이 테이블의 실제 노출·권한은 별도 승인된 점검/계획에서 확인할 사항이다. 경고나 노출을 해결했다고 주장하지 않는다.

## 검증

- pytest: 외부 네트워크와 운영 DB/비공개 설정 읽기를 차단한 인메모리 합성 데이터. 원자적 실패 복원, 중복 요청, 충돌, 부분 과거 보정, 나중 확인, 취소, 미국 원가, 수량 0, 후속 기록 보호 등.
- node 테스트: 정정 화면의 비활성 조건, 명시적 확인, 과거 근거 부족, 같은 요청 재시도, 기존 화면 회귀. 실제 브라우저 클릭 검증과 구분한다.
- scripts/verify_ledger_corrections.py: 별도 127.0.0.1:55438 trust QA PostgreSQL만 허용. 새 합성 DB를 생성하고 마이그레이션 두 번, 실제 SQL/페이지 조회, 동시 요청, 작업 잠금, 취소, API 스키마·조회 전용 가짜 나무 응답을 검증한다. 비공개 연결 파일을 읽지 않는다.
- scripts/local_ui_preview.py --trust-local-port 55438 --port 8563 --ledger-corrections: 로컬 합성 앱. 실제 자산 자료와 가격 API는 사용하지 않는다.

100만원 누락 예시: 검증 CMA → 과거 출금 누락 → 2026-09-30 → 1,000,000원 → 사유 → 미리보기. 검증 자료에는 시작 기준 및 10/5·6·7 기록에 같은 잔고 오차가 포함돼 있다. 운영 기록이 같은지는 운영에서 직접 확인해야 한다.
